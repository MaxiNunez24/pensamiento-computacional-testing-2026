Tu catálogo con Python

Esta clase es optativa, y es para hacer

No hace falta para el proyecto del curso. Pero al terminarla tenés una página publicada en internet, con un link para compartir. Todos los ejercicios corren acá mismo, en el navegador.

El problema

Sección titulada «El problema»

Esta clase salió de una pregunta real. Alguien que vende productos quiere lo que tienen muchos emprendimientos: un catálogo en internet, con una tarjeta por producto, el precio, y un botón que abre WhatsApp con el mensaje ya escrito. Y la pregunta que vino detrás fue:

“¿Y lo que están aprendiendo, para qué sirve? ¿Todavía no saben hacer nada útil?”

Hagamos la cuenta. Los productos están en una planilla. Para armar el catálogo hay que:

Paso¿Lo sabés hacer?
Leer la planilla✅ Lo hiciste con el bot del SiGeS: csv.DictReader
Recorrer los productos, uno por uno✅ Un for
Armar el texto de cada tarjeta con los datos✅ Un f-string
Guardar el resultado en un archivo✅ with open(..., "w")
Que el resultado sea una página web❌ Esto es lo nuevo
Publicarla con un link🟡 Casi: ya subís cosas a GitHub

La parte difícil —leer los datos, recorrerlos y decidir qué mostrar— ya la sabés. Lo que falta es el idioma de las páginas web. Y es lo más fácil de todo.

La analogía de la clase

HTML y CSS son la ropa. La lógica es el cuerpo. Una página escrita a mano se ve igual de linda, pero si cambia un precio, alguien la tiene que editar a mano; si agregás un producto, a mano. La que arma Python se actualiza sola: cambiás la planilla, corrés el programa, y está.

Una página es un archivo de texto

Sección titulada «Una página es un archivo de texto»

Una página web es un archivo de texto que termina en .html. Adentro, el contenido va entre etiquetas que le dicen al navegador qué es cada cosa:

  • <h2> abre un título, y </h2> lo cierra. Lo de adentro es el texto del título.
  • <p> es un párrafo.
  • Casi todas las etiquetas se abren y se cierran: la de cierre es igual, con una /.

Y una etiqueta puede llevar atributos, que van adentro de la de apertura:

class="precio" no se ve en la página: es un nombre que le ponemos a ese párrafo, para que los estilos sepan cuál es el precio y lo pinten grande y en negrita.

Una tarjeta entera es esto: una caja (<article>) con cosas adentro.

Fijate en la sangría: lo que está adentro del <article> va corrido a la derecha. Al navegador le da igual (no es Python), pero a vos te deja ver qué está adentro de qué.

Sección titulada «Que lo escriba Python»


Ahora viene lo tuyo. Una tarjeta es un texto, y vos ya sabés armar textos con los datos
adentro: un f-string.


Lo único nuevo: el texto de una tarjeta tiene varios renglones. Para eso, el string va entre
tres comillas:




Las comillas adentro de las llaves
Si el dato sale de un diccionario, adentro de las llaves usá comillas simples:
{producto['nombre']}. Con dobles, en un Python anterior al 3.12 se confunde con el final del
string y da error.

import csv
from urllib.parse import quote

def link_whatsapp(numero, nombre):
    return f"https://wa.me/{numero}?text=" + quote(f"Hola, quiero consultar por: {nombre}")

def tarjeta(producto, numero):
    return f"""
<article class="producto">
  <div class="producto__foto">{producto['emoji']}</div>
  <h2>{producto['nombre']}</h2>
  <p class="descripcion">{producto['descripcion']}</p>
  <p class="precio">$ {producto['precio']}</p>
  <a class="consultar" href="{link_whatsapp(numero, producto['nombre'])}">Consultar por WhatsApp</a>
</article>
"""

def leer_productos(ruta):
  with open(ruta, encoding="utf-8") as archivo:
      return list(csv.DictReader(archivo))

def pagina(titulo, productos, numero):
  tarjetas = ""
  for producto in productos:
      tarjetas += tarjeta(producto, numero)
  return f"""<!doctype html>
<html lang="es">
<head><meta charset="utf-8"><title>{titulo}</title><link rel="stylesheet" href="estilos.css"></head>
<body><header class="encabezado"><h1>{titulo}</h1></header><main class="catalogo">{tarjetas}</main></body>
</html>

Publicarlo en internet, gratis
Sección titulada «Publicarlo en internet, gratis»


GitHub publica páginas gratis: se llama GitHub Pages, y es justamente donde está publicada esta
plataforma.


    

  1. En GitHub, creá un repositorio nuevo público, por ejemplo catalogo.
    2. 

  2. Subí index.html y estilos.css. Con lo de Git que ya sabés (git add, git commit,
git push), o arrastrándolos en la página del repositorio, con Add file → Upload files.
    3. 

  3. En el repositorio: Settings → Pages. En Branch elegí main y la carpeta / (root), y
tocá Save.
    4. 

  4. Esperá uno o dos minutos y recargá esa página: arriba aparece el link, algo así como
https://tu-usuario.github.io/catalogo/.
    5. 



Ese link es tu catálogo. Se puede mandar por WhatsApp, poner en Instagram o imprimir en un QR.
Cada vez que generes la página de nuevo, la volvés a subir y el link muestra la versión nueva.


Lo que se sube es público
Cualquiera con el link ve la página, y el repositorio también. Ahí no van datos que no pondrías en
una vidriera: tu número de WhatsApp sí (es para que te escriban), una dirección particular no.

Para llevar
Sección titulada «Para llevar»


    

  • Una página web es un archivo de texto con etiquetas: <h2> título, <p> párrafo, <a href>
link, <img src> imagen. Casi todas se abren y se cierran.
    • 

  • HTML dice qué es cada cosa, CSS cómo se ve, y Python la arma con los datos. Por eso se
actualiza sola: los datos viven en la planilla.
    • 

  • Un f-string de tres comillas arma un texto de varios renglones con los datos adentro.
    • 

  • quote() deja un texto listo para ir adentro de un link.
    • 

  • GitHub Pages publica gratis lo que subas a un repositorio. index.html es la página que
abre la dirección.
    •
