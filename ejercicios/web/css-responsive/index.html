CSS IV · Que se vea bien en el celular

Antes de empezar

Usa lo de CSS III: Flexbox y Grid.

El problema

Sección titulada «El problema»

Mandaste el link de tu catálogo por WhatsApp. ¿Desde dónde lo abren? Desde el celular, casi todos. Y una página pensada para la pantalla de la compu, en un celular, es una pesadilla: letra diminuta, hay que hacer zoom, las fotos se salen del costado.

Una página responsive (que “responde” al tamaño) se ve bien en cualquier pantalla. No son dos páginas: es una sola, con reglas que cambian según el ancho.

La línea que no puede faltar

Sección titulada «La línea que no puede faltar»

Antes de cualquier CSS, esto va en el <head> de toda página:

Sin ella, el celular simula ser una pantalla de compu de unos 980 píxeles y achica todo para que entre: la letra queda diminuta, por más CSS que le pongas. Con ella, le decís “usá el ancho real del celular”. Es la primera causa de “mi página se ve chiquita en el celular”.

Media queries: reglas que dependen del ancho

Sección titulada «Media queries: reglas que dependen del ancho»

Una media query es un if de CSS: las reglas de adentro valen solo si se cumple la condición.

min-width: 600px quiere decir “si la pantalla mide 600 o más”. Fijate el orden: primero las reglas para el celular, y después, con min-width, lo que cambia cuando hay más lugar. Se llama primero el celular (mobile first), y es la forma recomendada, por dos motivos:

  • la mayoría de las visitas son desde el celular, así que esa es la versión principal;
  • es más fácil agregar cosas cuando hay lugar que sacarlas cuando no hay.
🌿

⭐ Fundamental ✓ Resuelto

Hacé que el catálogo tenga una columna en el celular y tres desde 600px de ancho. Primero el celular, después la media query.

Unidades que se adaptan
Sección titulada «Unidades que se adaptan»


Los píxeles son fijos. Para que las cosas se acomoden, hay unidades relativas:



























UnidadEs…Para…
%Un porcentaje del contenedorAnchos: width: 50%
remVeces la letra de la página (normalmente 16px)Tamaños de letra y espacios: font-size: 1.5rem
vw / vhUn 1% del ancho / alto de la pantallaUna portada que ocupe toda la pantalla: height: 100vh


Usar rem para la letra tiene un beneficio enorme: si alguien que ve poco agranda la letra en su
celular, tu página se agranda con ella. Con px, no.

Variables de CSS
Sección titulada «Variables de CSS»


En una página, el mismo color aparece veinte veces: en el título, en los botones, en los precios. Si
un día cambia el color de la marca, hay que buscarlos todos. Con variables, se escribe una vez:




    

  • Se definen con dos guiones adelante, y :root las hace valer para toda la página.
    • 

  • Se usan con var(--nombre).
    • 

  • Cambiás --principal en un solo lugar, y cambia en todos.
    • 



Es la misma idea que una variable de Python: un nombre para un valor que se usa en muchos lados.

Modo oscuro
Sección titulada «Modo oscuro»


Muchos usan el celular en modo oscuro. Tu página se puede enterar con una media query, y como
los colores están en variables, alcanza con cambiar las variables:




Todo lo que usa var(--fondo) y var(--texto) cambia solo. Esa es la gran ventaja de las
variables: el modo oscuro es redefinir dos o tres, no reescribir la página.

Para llevar
Sección titulada «Para llevar»


    

  • <meta name="viewport" content="width=device-width, initial-scale=1"> en el <head>, siempre.
    • 

  • Media queries: @media (min-width: 600px) { ... }, las reglas de adentro valen desde ese
ancho. Primero el celular, después lo que cambia en la compu.
    • 

  • Unidades relativas: % del contenedor, rem de la letra (respeta al que agranda la letra), vw/vh
de la pantalla.
    • 

  • img { max-width: 100%; height: auto; }: ninguna imagen se sale.
    • 

  • Variables: :root { --principal: #8a5a2b; } y var(--principal). Un cambio, y cambia todo.
    • 

  • Modo oscuro: @media (prefers-color-scheme: dark) y redefinir las variables.
