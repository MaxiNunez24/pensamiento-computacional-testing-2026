APIs con requests: pedirle datos a internet

Esta clase se hace en VS Code, no acá

Los ejercicios de la plataforma corren Python adentro del navegador, y desde ahí no se puede usar requests. Por eso esta clase se hace en tu compu, con VS Code: acá leés y copiás, y allá lo ejecutás. Necesitás internet.

El problema

Sección titulada «El problema»

Tu programa sabe solamente lo que vos le escribiste. Si querés que diga cuándo es el próximo feriado o muestre el dólar de hoy, tendrías que cambiar el número a mano todas las mañanas. Y si querés una foto distinta cada vez que tocás un botón, tendrías que tener miles de fotos guardadas.

Esos datos ya existen, actualizados, en otras computadoras. Lo que falta es que tu programa se los pueda pedir. Para eso están las APIs.

Qué es una API

Sección titulada «Qué es una API»

Una API es una dirección de internet que, en vez de devolverte una página para mirar, te devuelve datos para que los use tu programa.

Pensalo como un mozo: vos no entrás a la cocina, le hacés un pedido y te trae una respuesta. No te importa cómo la cocinaron.

Preparar VS Code

Sección titulada «Preparar VS Code»

Esta vez sí hay que instalar algo: requests, la librería que hace los pedidos, y pillow, que vamos a usar al final para mostrar las fotos en una ventana.

  1. Creá una carpeta nueva, por ejemplo apis, y abrila con File → Open Folder.

  2. Abrí la terminal (Terminal → New Terminal) y armá un entorno virtual, como hicimos con el bot del SiGeS:

    La línea de la terminal tiene que empezar con (.venv).

  3. Con el (.venv) a la vista, instalá las dos librerías:

  4. Creá un archivo perros.py. Lo ejecutás con el ▶ de arriba a la derecha.

Si dice que “la ejecución de scripts está deshabilitada”

Es PowerShell, que por seguridad no deja correr el archivo de activación. No hace falta cambiar nada de la compu: en la terminal, tocá la flechita al lado del + y elegí Command Prompt. Ahí .venv\Scripts\activate anda sin problema.

Si dice ModuleNotFoundError: No module named 'requests'

El ▶ está usando el Python de la compu y no el del entorno virtual, que es donde instalaste requests. Apretá Ctrl+Shift+P, escribí Python: Select Interpreter y elegí el que dice .venv. Después volvé a tocar el ▶.

Cuando algo sale mal
Sección titulada «Cuando algo sale mal»


Hay dos cosas distintas que pueden fallar:


    

  1. El pedido llega, pero lo que pediste no existe. Por ejemplo, una raza que no conocen. La
respuesta llega igual, con status_code 404.
    2. 

  2. El pedido ni siquiera llega: no hay internet, o el servidor no contesta. Ahí requests
tira una excepción, y si no la atrapás, el programa se corta.
    3. 



Las dos se atienden distinto. La primera con un if y la segunda con try / except, como en
la clase de Excepciones:




requests.exceptions.RequestException atrapa todos los errores de conexión: sin internet,
servidor caído, demasiada demora.


Probá: beagle, pug, husky, y después una que no exista, como firulais. Y si te animás,
desconectá el WiFi y probá de nuevo.

ArgentinaDatos: los datos del país
Sección titulada «ArgentinaDatos: los datos del país»


ArgentinaDatos es una API argentina, gratis y sin registrarse,
que junta en un solo lugar un montón de datos públicos: feriados, cotizaciones del dólar,
inflación, riesgo país, tasas de plazo fijo. Todas sus direcciones empiezan igual,
https://api.argentinadatos.com/v1/, y lo que cambia es el final. La lista completa está en
su documentación.


Arrancamos por lo más cercano: los feriados.

¿Cuándo es el próximo?
Sección titulada «¿Cuándo es el próximo?»


Para eso hay que comparar cada fecha con la de hoy. date.today() ya lo usaste en
el bot. Lo nuevo es date.fromisoformat, que convierte
el texto "2026-12-08" en una fecha de verdad, de las que se pueden comparar y restar:




📦 Lo nuevo de las fechas
    

  • date.fromisoformat("2026-12-08") pasa el texto a fecha. Anda con fechas escritas
año-mes-día, que es como vienen casi todas las APIs.
    • 

  • Restar dos fechas da la distancia entre las dos, y .days es esa distancia en días.
    • 

  • Una fecha sabe sus partes: fecha.year, fecha.month, fecha.day. Y
fecha.weekday() dice el día de la semana, con un número: 0 es lunes y 6 es domingo.
    • 

Como los feriados vienen ordenados, el primero que está después de hoy es el próximo: ahí
el break corta el bucle, porque no hace falta seguir mirando.

Algo nuevo: historial[-30:]
Con los dos puntos adentro de los corchetes no pedís un elemento sino un pedazo de la
lista. historial[-30:] es “desde el trigésimo contando del final, hasta el final”: los últimos
30. Otros ejemplos: lista[:3] son los tres primeros, y texto[:7] los primeros 7 caracteres
de un texto.

Todo junto: un perro por clic
Sección titulada «Todo junto: un perro por clic»


Ahora se junta con Tkinter: una ventana con un botón, y
cada vez que lo tocás aparece la foto de un perro nuevo. Archivo nuevo, ventana_perros.py:




Lo nuevo está todo adentro de otro_perro:


    

  • Dos pedidos. El primero trae el JSON, que dice dónde está la foto. El segundo baja la
foto misma. Como una foto no es JSON, en vez de .json() se usa .content: los bytes
crudos de la imagen.
    • 

  • Image.open(io.BytesIO(imagen)). Tkinter solo no sabe abrir fotos JPG, y por eso está
Pillow (PIL). Image.open espera un archivo, y io.BytesIO hace que los bytes que
bajamos se comporten como un archivo, sin guardarlo en el disco.
    • 

  • foto.thumbnail((400, 400)) la achica para que entre en 400 × 400 sin deformarla. Algunas
fotos vienen enormes.
    • 

  • ImageTk.PhotoImage la convierte a algo que un Label de Tkinter pueda mostrar.
    • 



La línea que parece que sobra: cuadro.image = foto_tk
Borrala y probá: el cuadro queda vacío. La foto es una variable local de la función, y cuando
la función termina, Python la tira porque nadie más la usa. Tkinter no cuenta como alguien que la
usa. Guardándola como atributo del Label, la foto vive mientras viva el Label.


La ventana se congela un segundo
Mientras baja la foto, la ventana no responde: el programa está esperando la respuesta y no puede
hacer otra cosa. Con fotos chicas y buen internet casi ni se nota. Arreglarlo del todo se hace con
hilos, y eso queda para más adelante.
