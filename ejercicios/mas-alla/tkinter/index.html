Tkinter: ventanas con botones

Esta clase se hace en VS Code, no acá

Los ejercicios de la plataforma corren Python adentro del navegador, y el navegador no deja que un programa abra ventanas propias. Por eso esta clase se hace en tu compu, con VS Code: acá leés y copiás, y allá lo ejecutás.

El problema

Sección titulada «El problema»

El sistema de asistencias por consola anda, pero pensá en quien lo va a usar: una preceptora que nunca vio una terminal, frente a un cursor que parpadea esperando que escriba un número de menú.

Lo que esa persona espera es una ventana: un lugar donde escribir el DNI, un botón que diga Registrar y un cartel que conteste. Eso se puede hacer con lo que ya sabés, más una sola librería: Tkinter.

Tkinter ya está en tu compu

Viene incluido con Python: no hay que instalar nada con pip ni armar un entorno virtual. Si tenés Python y VS Code, ya está todo.

Preparar VS Code

Sección titulada «Preparar VS Code»

Si ya venís usando VS Code con Python, saltá al paso 4.

  1. Python instalado. Si no lo tenés, seguí Instalar Python. Las opciones que vienen marcadas por defecto ya incluyen Tkinter.

  2. VS Code con la extensión de Python (la de Microsoft). Está en Instalar VS Code.

  3. Una carpeta para la clase. Creá una carpeta nueva, por ejemplo ventanas, y abrila con File → Open Folder (Archivo → Abrir carpeta).

  4. Probá que Tkinter ande. Abrí la terminal de VS Code con Terminal → New Terminal (Terminal → Nuevo terminal) y escribí:

    Tiene que aparecer una ventanita con dos botones, Click me! y QUIT. Si aparece, está todo listo: cerrala y seguí.

  5. Creá un archivo nuevo con el nombre ventana.py. Para ejecutarlo, tocá el ▶ que está arriba a la derecha (Run Python File).

Nunca le pongas tkinter.py a tu archivo

Si tu archivo se llama tkinter.py, cuando escribas import tkinter Python se importa tu archivo en vez de la librería, y nada anda. Ponele cualquier otro nombre: ventana.py, saludo.py, asistencia.py.

Si algo no arranca

  • No aparece el ▶: fijate que el archivo termine en .py y que la extensión de Python esté instalada.
  • Dice que no encuentra Python: apretá Ctrl+Shift+P, escribí Python: Select Interpreter y elegí el Python que instalaste.
  • No ves la ventana: a veces se abre detrás de VS Code. Buscala en la barra de tareas o con Alt+Tab.

Qué hace mainloop()

Sección titulada «Qué hace mainloop()»

Un programa de consola corre de arriba abajo y termina. Una ventana no puede hacer eso: tiene que quedarse esperando a que toques algo. mainloop() es un bucle que hace justamente eso: se queda mirando qué toca el usuario, y no termina hasta que cerrás la ventana.

Se parece a input(), que también frena el programa hasta que escribís algo. La diferencia es que input() espera una respuesta, y mainloop() espera todo el tiempo, cualquier cosa.

Textos y botones
Sección titulada «Textos y botones»


Las cosas que van adentro de una ventana se llaman widgets: un texto, un botón, una caja para
escribir. Cada uno es un objeto, y se crea diciéndole en qué ventana va:




    

  • tk.Label es un texto que el usuario lee pero no puede cambiar.
    • 

  • tk.Button es un botón.
    • 

  • .pack() lo pone en la ventana, uno abajo del otro. Si te olvidás del .pack(), el widget
existe pero no se ve.
    • 

  • pady=20 le deja 20 píxeles de aire arriba y abajo.
    •

Esto es nuevo: el programa espera a que lo llames
Hasta ahora vos decidías cuándo se ejecutaba cada función, llamándola en tu código. Con una
ventana, la que decide es la persona que toca el botón. Vos solo dejás la función preparada y
le avisás al botón cuál es. A esto se le dice programación por eventos: cada clic es un evento.


Leer lo que escriben
Sección titulada «Leer lo que escriben»


Para que el usuario escriba, está tk.Entry: una caja de una línea. Lo que escribió se lee con
.get(), que siempre devuelve texto, como input():




El primer Label y el botón no se guardan en una variable: se crean y se ponen en la misma línea
con .pack(). Se puede hacer cuando no los vas a volver a tocar. A entrada y a mensaje sí los
necesitamos después, adentro de saludar, y por eso tienen nombre.

Números, errores y carteles
Sección titulada «Números, errores y carteles»


Ahora algo del proyecto: el porcentaje de asistencia. Se escriben las clases dadas y las
faltas, y la ventana dice si llega al 85 %.


Como .get() devuelve texto, hay que pasarlo a número con int(). Y si escriben diez en vez
de 10, int() tira un ValueError: lo atrapamos con try / except, como en la clase de
Excepciones, y avisamos con un cartel (messagebox):




Tres cosas nuevas:


    

  • messagebox.showerror(título, mensaje) abre un cartel de error con un botón OK. Hay
también showinfo (información) y showwarning (advertencia). Se importa aparte, con
from tkinter import messagebox.
    • 

  • return solo, sin nada, corta la función ahí. Si el dato estaba mal, no tiene sentido
seguir calculando.
    • 

  • .grid() en vez de .pack(): acomoda los widgets en una grilla de filas y columnas,
como una planilla. row es la fila, column la columna (las dos empiezan en 0), y
columnspan=2 hace que el botón ocupe las dos columnas. En una misma ventana usá o pack
o grid, no los dos mezclados.
    • 



fg es el color de las letras (foreground): "green", "red", "blue"… o un código como
"#ff4d6d", como en CSS.

Ordenarlo con una clase
Sección titulada «Ordenarlo con una clase»


Cuando la ventana crece, tantas variables sueltas se vuelven un lío. Lo que ya sabés de POO
lo ordena: la ventana es un objeto, los widgets son sus atributos y lo que hacen los botones
son sus métodos. Por ejemplo, un contador de clics:




    

  • command=self.sumar: el método del objeto, otra vez sin paréntesis.
    • 

  • self.cantidad guarda la cuenta entre un clic y el siguiente. Sin la clase, tendría que ser
una variable de afuera de la función, y Python no te deja cambiarla desde adentro sin un truco
extra (global). El objeto la guarda sin vueltas.
    •
