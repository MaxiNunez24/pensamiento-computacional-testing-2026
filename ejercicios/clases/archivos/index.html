← Volver a la teoría de esta clase

El problema

Sección titulada «El problema»

Todo lo que hiciste hasta ahora vive en la memoria RAM: existe mientras el programa corre y desaparece cuando se cierra.

Cerrás el programa, lo volvés a abrir… y la lista no está más. Si tuvieras que cargar cien alumnos a mano cada vez que arrancás, el programa sería inútil.

Para que los datos sobrevivan, hay que sacarlos de la RAM y ponerlos en el disco: un archivo.

La jerarquía en una frase

La RAM es rápida pero se borra al apagar. El disco es más lento pero recuerda. Cuando querés que algo dure entre ejecuciones, va al disco.

Abrir un archivo

Sección titulada «Abrir un archivo»

open() recibe dónde está el archivo y para qué lo abrís (el modo):

ModoQué haceSi el archivo no existe
"r"Leer (es el que se usa por defecto)💥 Error
"w"Escribir borrando todo lo anteriorLo crea
"a"Escribir agregando al finalLo crea
"x"Crear, y fallar si ya existeLo crea

"w" borra sin preguntar

Abrir con "w" un archivo que ya tiene contenido lo vacía en el acto, antes incluso de que escribas nada. Si querés sumar sin perder lo que había, el modo es "a".

Siempre with

Sección titulada «Siempre with»

Ese archivo.close() del ejemplo es un problema esperando: si el programa falla entre el open y el close, el archivo queda abierto y podés perder lo que escribiste.

Por eso en Python siempre se usa with:

El with se encarga de cerrarlo pase lo que pase. No es una preferencia de estilo: es la forma correcta.

Rutas: dónde busca Python
Sección titulada «Rutas: dónde busca Python»


Cuando escribís open("datos.txt"), Python lo busca desde la carpeta donde estás parado, no
desde donde está el archivo .py. Es la causa número uno del FileNotFoundError.




Si te tira FileNotFoundError
No es que el archivo no exista: es que no está donde Python está mirando. Antes de pelearte con
la ruta, preguntale dónde está parado:

Path arma las rutas correctamente en Windows, Linux y macOS sin que tengas que pensar en las barras.


Los archivos de esta página son de mentira
Python corre acá adentro del navegador, con un sistema de archivos virtual: los archivos que
creás existen de verdad para el programa, pero viven en la pestaña y desaparecen al recargar. No
toca nada de tu compu. En VS Code, el mismo código escribe archivos posta.

La copia de seguridad
 ✓ Resuelto  
 
 
Completá respaldar(ruta, fecha): copia el archivo a uno nuevo con la fecha en el nombre, y
devuelve cómo se llamó.
El original queda intacto.
La copia que salva el año
El sistema va a vivir en una netbook del CFP que se apaga de un tirón. Una copia por día, con la
fecha en el nombre, es la diferencia entre perder un día y perder el año.
Y por eso el nombre lleva la fecha y no algo como asistencia-backup.txt: un solo archivo de
respaldo se pisa a sí mismo, y el día que te das cuenta de que los datos estaban mal ya lo
respaldaste tres veces.
