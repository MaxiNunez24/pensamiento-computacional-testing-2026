Condicionales — if / elif / else

← Volver a la teoría de esta clase

El problema

Sección titulada «El problema»

Hasta ahora tus programas hacían siempre lo mismo, en el mismo orden. Pero la mayoría de las cosas útiles necesitan decidir:

  • Si la nota es 6 o más → aprobó. Si no → desaprobó.
  • Si el carrito supera los $50.000 → envío gratis.
  • Si la contraseña coincide → entra.

Para eso está el if.

La forma básica

Sección titulada «La forma básica»

Tres cosas que importan:

  • Después de la condición van dos puntos :.
  • Lo que está indentado (corrido a la derecha) es lo que pasa si la condición se cumple.
  • El else es opcional: si no hay nada que hacer cuando no se cumple, no lo pongas.

La indentación no es decoración

En Python, los espacios de la izquierda son parte del código. Le dicen qué líneas están adentro del if y cuáles afuera.

Si movés esa última línea cuatro espacios a la derecha, cambia lo que hace el programa.

Comparaciones

Sección titulada «Comparaciones»
OperadorSignifica
==¿son iguales?
!=¿son distintos?
> <mayor / menor
>= <=mayor o igual / menor o igual

= y == no son lo mismo

= guarda un valor (edad = 18). == pregunta si dos cosas son iguales (edad == 18). Confundirlos es un clásico, y Python te lo marca como error de sintaxis.

Más de dos caminos: elif
Sección titulada «Más de dos caminos: elif»


Cuando hay varias opciones, se encadenan con elif (else if):




El orden importa muchísimo. Python prueba las condiciones de arriba hacia abajo y se queda con
la primera que se cumple; el resto ni las mira.


Por qué este orden y no otro
Si pusieras nota >= 6 primero, un 10 entraría por ahí y diría “Aprobado”, porque 10 también es
mayor o igual a 6. Nunca llegaría a “Excelente”. Con elif conviene ir de lo más exigente a lo
menos exigente.

Un detalle que te va a ahorrar líneas
Sección titulada «Un detalle que te va a ahorrar líneas»


Cuando una condición ya es verdadera o falsa por sí misma, no hace falta el if:




edad >= 18 ya es un True o un False. Envolverlo en un if para después guardar True o
False es dar una vuelta de más. Las dos versiones funcionan; la segunda se lee mejor.
