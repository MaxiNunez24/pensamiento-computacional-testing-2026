SQLite — los datos en una base

La primera vez tarda un poquito más

El primer ejercicio que ejecutes baja la parte de Python que maneja bases de datos. Son unos segundos, una sola vez: después queda guardada.

El problema

Sección titulada «El problema»

Hasta ahora, lo que un programa guardaba se perdía al cerrarlo. Para que el sistema de asistencias recuerde, los datos tienen que quedar en el disco. La pregunta es dónde.

Lo más directo sería un archivo de texto. Pero en el CFP pasa algo que en nuestros ejercicios no pasaba nunca: dos personas usando el sistema al mismo tiempo. Dos preceptoras marcando asistencia en dos cursos, en el mismo minuto.

Lo medimos, y con archivos pasan dos cosas:

  • Con dos personas guardando a la vez, una de las dos marcas se pierde. Sin ningún error: el sistema dice que guardó y no guardó.
  • Si se corta la luz justo mientras se escribe, el archivo queda ilegible entero. No la última marca: todo.

Una base de datos resuelve las dos cosas. Y la que vamos a usar, SQLite, tiene una ventaja enorme: viene con Python. No se instala nada.

Una tabla es una planilla con reglas
Sección titulada «Una tabla es una planilla con reglas»


Una base de datos guarda tablas. Y una tabla se parece mucho a las planillas que usan en el
CFP: columnas con nombre, y una fila por alumno.

























dniapellidonombreactivo
30111222PerezAna1
28999888GomezBeto1


La diferencia es que la tabla tiene reglas. Cada columna tiene un tipo, y se puede decir que
una columna no se repite nunca: eso se llama PRIMARY KEY. Para nosotros, el DNI.


Es lo mismo que hacíamos a mano en “El curso que no deja repetir”, pero ahora lo cuida la base.


Para hablarle a la base se usa un lenguaje propio, SQL. Se escribe como un texto adentro de
Python, y sqlite3 se lo pasa a la base:




con es la conexión: por ahí pasa todo lo que le pedimos a la base.

Agregar: el signo de pregunta
Sección titulada «Agregar: el signo de pregunta»


Para agregar una fila se usa INSERT. Y acá hay una regla que no se rompe nunca: los valores
no se pegan en el texto del SQL. Van con ?, y se pasan aparte:




Un ? por cada valor, y después los valores en el mismo orden, en una tupla.


¿Por qué tanta vuelta, si con un f-string quedaría más corto? Porque el SQL también usa comillas.
Si un apellido tiene una —D’Alessandro, O’Connor—, esa comilla cierra el texto adentro del
SQL y rompe todo. Con ?, sqlite3 se encarga de poner cada valor bien, tenga lo que tenga.

Dar de baja no es borrar
Sección titulada «Dar de baja no es borrar»


En la clase de POO, dar de baja a un alumno era cambiar activo a False, nunca borrarlo:
si se borra, se pierde su asistencia de todo el año y los números del cierre dejan de dar.


En la base es igual. Para cambiar un dato se usa UPDATE:




El WHERE es lo más importante de esa línea
Un UPDATE sin WHERE cambia todas las filas de la tabla. Sin avisar, y sin deshacer.

De la fila al objeto: el repositorio
Sección titulada «De la fila al objeto: el repositorio»


Hasta acá, todo devuelve filas: tuplas con los datos. Pero el resto del sistema —el bot, la
pantalla de pasar lista— trabaja con objetos Alumno, que saben armar su nombre completo o
decir si están listos.


Entonces hay que convertir. Y esa conversión va en un solo lugar: un archivo que se llama
repositorio.py, con funciones como buscar_alumno, guardar_alumno o dar_de_baja. Todo lo
que toca la base vive ahí adentro, y ningún otro archivo del sistema escribe SQL.


¿Por qué tanto cuidado? Porque así, si mañana cambia la base, se cambia un solo archivo. El
resto del programa pide un Alumno y recibe un Alumno, sin enterarse de dónde salió.


 
 🌶️

 ✓ Resuelto

Alumno —la clase de POO, que ya está definida— armado con los datos de la fila. O None si no
está.
 
  
 📶 La primera vez se descarga Python (unos 10 MB). Si estás con datos del celular, mejor esperá a tener WiFi. Después queda guardado y ya no se baja más.

class Alumno:

En tu compu
Sección titulada «En tu compu»


En VS Code es todo igual, con dos diferencias.


La base es un archivo. Con sqlite3.connect("asistencias.db") se crea asistencias.db en la
carpeta del proyecto, y ahí quedan los datos.


Hay que confirmar los cambios. Lo que agregás, cambiás o das de baja queda pendiente hasta
