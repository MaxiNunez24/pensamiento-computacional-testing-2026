La función print()

← Volver a la teoría de esta clase

El problema

Sección titulada «El problema»

Una computadora puede hacer millones de cuentas por segundo. Pero si no te muestra el resultado, es como si no hubiera hecho nada: el número queda adentro de la máquina y se pierde.

print() es la forma de decirle “esto, mostrámelo”.

Comillas: texto vs. otra cosa

Sección titulada «Comillas: texto vs. otra cosa»

Esta es la primera trampa del lenguaje.

Con comillas, "Hola" es un texto (un string). Sin comillas, Python cree que Hola es el nombre de algo que vos definiste antes — y como no existe, se queja.

Sirven las comillas dobles " o simples ', mientras abras y cierres con la misma.

Sección titulada «Mostrar varias cosas juntas»


print() acepta varias cosas separadas por comas, y las muestra con un espacio en el medio:




Fijate que 30 va sin comillas: es un número, no un texto. print() se banca ambos.


La coma no es lo mismo que el +
La coma junta cosas para mostrarlas. El + intenta sumarlas, y sumar un texto con un número
no significa nada.

f-strings: meter valores adentro del texto
Sección titulada «f-strings: meter valores adentro del texto»


Cuando el texto y los datos se mezclan mucho, las comas se vuelven incómodas. Para eso están las
f-strings: una f antes de la comilla, y las variables entre llaves {}.




Se lee de corrido, que es justamente la gracia.


Si te olvidás la f
Sin la f, las llaves son texto común y salen tal cual. Es un error silencioso: no rompe, solo
muestra cualquier cosa. Si ves llaves en tu salida, fijate la f.

Los tres errores que vas a cometer
Sección titulada «Los tres errores que vas a cometer»























ErrorQué pasó
NameError: name 'Hola' is not definedTe faltaron las comillas: Python creyó que era el nombre de algo.
SyntaxError: unterminated string literalAbriste una comilla y no la cerraste.
TypeError: can only concatenate strUsaste + entre texto y número. Probá con coma o f-string.


Leé el error de abajo para arriba
Python te dice el tipo de error en la última línea y en qué línea de tu código pasó. Con esas
dos cosas ya sabés dónde mirar. No hace falta entender todo el bloque.
