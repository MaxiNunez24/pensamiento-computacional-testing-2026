Excepciones — cuando algo sale mal

El programa se cae

Sección titulada «El programa se cae»

Esto ya te pasó muchas veces:

El programa se frena ahí, en esa línea, y no sigue. Lo que Python está diciendo es: “me pediste algo que no puedo hacer”. Eso se llama una excepción.

Hasta ahora, cuando aparecía una, la solución era arreglar el código. Pero en el sistema del CFP los datos no los escribimos nosotros: los escriben treinta personas en un formulario, y alguna va a poner “doce” donde iba un número. El programa no puede caerse cada vez que pasa eso.

Las que ya conocés

Sección titulada «Las que ya conocés»

Atajarla: try y except
Sección titulada «Atajarla: try y except»


try quiere decir “intentá”. Se pone alrededor de lo que puede salir mal, y abajo, en except,
lo que hay que hacer si sale mal:




Si int() puede, se sigue normal y el except no se ejecuta. Si no puede, Python salta directo
al except —lo que quedaba del try no se ejecuta— y el programa sigue vivo.


 
 🌱 
Intentar, y si no se puede, None
 ✓ Resuelto

Nunca un except solo
Sección titulada «Nunca un except solo»


Se puede escribir except: sin nombre, y ataja cualquier excepción. Parece más cómodo. No lo es:




Esa función siempre devuelve None, para cualquier texto. El error de tipeo tira un NameError,
el except: lo ataja callado, y nadie se entera de que el programa está roto.

Levantar las tuyas: raise
Sección titulada «Levantar las tuyas: raise»


Hasta acá atajaste excepciones. Ahora al revés: las vas a levantar vos.


En la clase del bot, el Alumno decía si estaba listo con problemas(). Pero hay datos que están
tan rotos que el alumno no debería ni existir: un DNI con letras no es un alumno a medio cargar,
es un error. Para eso está raise:




raise corta el __init__ ahí mismo. El objeto no llega a crearse, y quien lo quiso crear
recibe un ValueError con tu mensaje. Es la misma excepción que tira int("doce"), porque es el
mismo problema: el valor no sirve.


 
 🌿 
El Alumno que no acepta cualquier DNI
 ✓ Resuelto  
 
 
Hacé que el Alumno no se pueda crear con un DNI roto: si no es solo números, o no tiene 7 u
8, levantá un ValueError con un mensaje que diga DNI.

Atajar, anotar y seguir
Sección titulada «Atajar, anotar y seguir»


Con el Alumno que ya no acepta cualquier cosa, falta lo último: que un alumno roto no frene a
los demás. Es lo que hace el bot: los que están bien se cargan, y los rotos quedan anotados con su
motivo para que los mire una persona.


El truco es except ... as e: además de atajar la excepción, te la guarda en e, con su
mensaje adentro.




 
 🌿 
Que uno roto no frene a todos
 ✓ Resuelto  
 
 
Completá inscribir_todos(filas): que cree un Alumno por fila, y que uno roto no frene a los
demás. Los que se pudieron crear van a inscriptos; el mensaje de los que no, a errores.
El Alumno que levanta ValueError ya está hecho (es el del ejercicio anterior).
 
  
 📶 La primera vez se descarga Python (unos 10 MB). Si estás con datos del celular, mejor esperá a tener WiFi. Después queda guardado y ya no se baja más.  
  
 📌 Esto ya está cargado — no hace falta que lo escribas: 
class Alumno:
  def __init__(self, dni, apellido, nombre):
      if not dni.isdigit() or len(dni) not in (7, 8):
          raise ValueError(f'el DNI "{dni}" tiene que ser solo números, 7 u 8')
      self.dni = dni
      self.apellido = apellido
      self.nombre = nombre

La base también dice que no
Sección titulada «La base también dice que no»


En la clase de SQLite, para no repetir un DNI, buscabas antes de insertar. Hay otra forma:
intentar el INSERT y que la base te diga que no. Cuando algo rompe una regla de la tabla —como
repetir un PRIMARY KEY—, sqlite3 levanta sqlite3.IntegrityError.


 
 🌿 
Que la base diga que no
 ✓ Resuelto  
 
 
Completá agregar(con, dni, apellido, nombre): que intente el INSERT y devuelva True si
entró, o False si la base dijo que no porque el DNI ya estaba.
 
  
 📶 La primera vez se descarga Python (unos 10 MB). Si estás con datos del celular, mejor esperá a tener WiFi. Después queda guardado y ya no se baja más.  
  
 📌 Esto ya está cargado — no hace falta que lo escribas: 
import sqlite3

def base_nueva():
  con = sqlite3.connect(":memory:")
  con.execute("CREATE TABLE alumnos (dni TEXT PRIMARY KEY, apellido TEXT, nombre TEXT)")
  return con

Para llevar
Sección titulada «Para llevar»


    

  • Una excepción es Python diciendo “no puedo hacer esto”. Su nombre dice qué pasó.
    • 

  • try alrededor de lo que puede fallar; except NombreDelError: con lo que hay que hacer si
falla. El programa sigue vivo.
    • 

  • Nunca except: solo: se come tus propios errores y los esconde.
    • 

  • raise ValueError("...") frena todo cuando un dato no sirve. Un Alumno con el DNI roto no
llega a existir.
    • 

  • except ... as e te guarda la excepción: con eso anotás el motivo y seguís con el siguiente.
    • 

  • La base también levanta las suyas: sqlite3.IntegrityError cuando se rompe una regla de la tabla.
    •
