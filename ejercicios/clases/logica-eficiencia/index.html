Eficiencia — que ande y que salga barato

“Anda” es el piso, no el techo

Sección titulada «“Anda” es el piso, no el techo»

Todos los ejercicios que hiciste hasta ahora tenían un solo criterio: que los tests pasaran.

Los de esta clase tienen dos. Primero que ande — eso no cambia. Y después, cuánto le costó andar: los mismos tests, pero corriendo tu solución con 10 datos, con 100 y con 1.000, para ver qué le pasa a tu programa cuando el problema crece.

Porque el problema siempre crece. La lista de tres alumnos con la que probás es la lista de cuarenta mil que va a tener el sistema el día que funcione.

Qué es un “paso”

Sección titulada «Qué es un “paso”»

El medidor cuenta cuántas líneas de tu código ejecuta Python. Nada más que eso: si tu for da mil vueltas y adentro tiene dos líneas, son unos dos mil pasos.

Es una medida grosera a propósito. No sirve para comparar dos soluciones que están a un 10% una de otra; sirve para lo que importa acá, que es ver la diferencia entre 900 y 400.000.

Por qué sum() cuenta como un solo paso

Las funciones que ya vienen con Python (sum, max, sorted, set…) están escritas en C, y el contador solo mira tus líneas. Así que sum(numeros) figura como 1 paso y tu for equivalente como 2.000.

No es trampa del medidor: es lo que realmente pasa. Ese recorrido igual existe, pero lo hace código compilado que corre entre 10 y 100 veces más rápido que un bucle escrito por vos. Apoyarte en las herramientas del lenguaje es la optimización.

Lo que sí conviene tener claro: rápido no es gratis. sorted(lista) es una barbaridad de eficiente, pero sigue costando más que recorrer la lista una vez. Cuando dos caminos usan funciones de Python, el contador ya no te alcanza para elegir — ahí hay que pensar.

Las insignias

Sección titulada «Las insignias»

Cuando los tests pasan, aparece una tarjeta con la medición y una de estas cuatro:

Qué significa
🏆 ÓptimoNo le estás haciendo repetir trabajo a la máquina.
⚡ EficienteRecorrés los datos lo justo. Hay una variante todavía más barata.
🟡 Se puede mejorarAnda bien, pero hacés de más. Suele ser un recorrido que sobra.
🐢 Fuerza brutaProbás muchísimas más cosas de las necesarias. Con datos de verdad, no termina.

Se guarda tu mejor marca, así que podés probar otra idea sin miedo a perder la insignia que ya te ganaste.

Las tres formas

Sección titulada «Las tres formas»

Toda solución que escribas va a tener una de estas tres formas. Reconocerla de un vistazo es, básicamente, todo el tema.

El bucle honesto
 
total = 0
for i in range(1, n + 1):
    total += i
return total
 
⏱️ unos 20.000 pasos con n = 10.000
 
Da una vuelta por cada número. Con n diez veces más grande, tarda diez veces más. Es la forma ⚡ una sola vuelta del croquis.
 
 
Delegarlo en Python
 
return sum(range(1, n + 1))
 
⏱️ 1 paso tuyo
 
El recorrido sigue existiendo, pero lo hace sum() en C. Muchísimo más rápido que tu for… aunque todavía depende de n.
 
 
La cuenta de Gauss
 
return n * (n + 1) // 2
 
⏱️ 1 paso, y con n = un billón también
 
Acá no hay recorrido en ningún lado. Es la única de las tres que no depende del tamaño: la forma 🏆 del croquis.

Todos estos funcionan. La diferencia está en lo que le hacen hacer a la

Comparar cada uno con todos
 
for i in range(len(numeros)):
    for j in range(i + 1, len(numeros)):
        if numeros[i] == numeros[j]:
            return True
return False
 
⏱️ más de 300.000 pasos con 600 números (tuvimos que cortarlo)
 
Un bucle adentro de otro. Cada número se compara con todos los que le siguen: es la grilla 🐢 del croquis. Con 6.000 números serían cien veces más.
 
 
Una sola vuelta, anotando lo visto
 
vistos = set()
for n in numeros:
    if n in vistos:
        return True
    vistos.add(n)
return False
 
⏱️ unos 1.800 pasos con 600 números
 
Preguntarle a un set si algo está adentro es instantáneo: no recorre nada. Por eso alcanza con una vuelta.
 
 
Contar antes y después
 
return len(set(numeros)) != len(numeros)
 
⏱️ 1 paso tuyo
 
El set descarta los repetidos al armarse. Si quedaron menos elementos, es porque había repetidos. El recorrido lo hace Python.

 ✓ Resuelto   
 
 
Escribí mas_larga(palabras), que devuelve la palabra con más letras. Si dos empatan, la primera.

 💡 Pistas para pensar el costo 
     
  1. Es el mismo esquema que "el número más alto" que ordenaste en la clase anterior, pero comparando len(palabra) en vez del valor.
  2. Ojo con el empate: si comparás con >= en vez de >, te vas a quedar con la última de las que empatan, no con la primera.
  3. Y una vez que te salga: max() acepta un parámetro key, que le dice según qué comparar. ¿Qué función devuelve la cantidad de letras?

 🔬 Otros caminos, y lo que cuesta cada uno 

Todos estos funcionan. La diferencia está en lo que le hacen hacer a la
        máquina.

 
 
Comparar cada palabra con todas
 
for p in palabras:
    es_la_mas_larga = True
    for otra in palabras:
        if len(otra) > len(p):
            es_la_mas_larga = False
    if es_la_mas_larga:
        return p
 
⏱️ unos 15.000 pasos con 500 palabras… y podrían ser 250.000
 
La grilla 🐢: por cada palabra, las comparás con todas. Acá zafa porque en estos datos la más larga aparece temprano y corta; si estuviera al final, se pasaría del tope del medidor. Una solución que depende de tener suerte con los datos no es una solución.
 
 
Una vuelta, acordándote de la mejor
 
mejor = palabras[0]
for p in palabras:
    if len(p) > len(mejor):
        mejor = p
return mejor
 
⏱️ unos 1.000 pasos con 500 palabras
 
Una sola pasada. Esta es la solución "correcta de manual", y en la mayoría de los problemas es la que vas a querer.
 
 
Decirle a Python según qué comparar
 
return max(palabras, key=len)
 
⏱️ 1 paso tuyo
 
max ya sabe recorrer y quedarse con el mejor; con key=len le decís que "mejor" significa "más letras". Y en los empates devuelve el primero, justo lo que pedía el enunciado.

Pares que suman un total
 ✓ Resuelto   
 
 
Escribí pares_que_suman(numeros, objetivo): cuántas parejas de números distintos de la lista
suman exactamente objetivo. La pareja (2, 8) y la (8, 2) son la misma y cuentan una sola vez.
Los números de la lista nunca se repiten.
Este es el más difícil de la clase, y el que mejor muestra de qué se trata todo esto: la solución
barata no es la misma solución “hecha más prolija”, es otra idea.

 ⏱️ Lo vamos a medir con:

  • pares_que_suman(list(range(300)), 299) — 300 números

 💡 Pistas para pensar el costo 
     
  1. La solución directa es probar todas las parejas. Con 300 números son unas 45.000 parejas. ¿Y con 3.000? (no son 450.000).
  2. Dale vuelta la pregunta. Estás parado en el número n y el objetivo es 10: en vez de probar contra todos, ya sabés qué número necesitás. ¿Cuál es?
  3. Si sabés exactamente qué número te falta, el problema pasa a ser "¿ese número ya lo vi?". Y eso, con un set, es instantáneo.
  4. Cuidado con contar dos veces: si al llegar al 7 contás la pareja con el 3, cuando llegues al 3 no la tenés que volver a contar. ¿Qué pasa si solo mirás hacia atrás, entre los que ya viste?
    5.  
 
 
 🔬 Otros caminos, y lo que cuesta cada uno 

Todos estos funcionan. La diferencia está en lo que le hacen hacer a la
        máquina.

 
 
Probar todas las parejas
 
total = 0
for i in range(len(numeros)):
    for j in range(i + 1, len(numeros)):
        if numeros[i] + numeros[j] == objetivo:
            total += 1
return total
 
⏱️ unos 90.000 pasos con 300 números
 
Anda perfecto y es fácil de leer. El problema es la grilla: multiplicar los datos por 5 multiplicó el trabajo por 25.
 
 
Preguntar por el que falta
 
vistos = set()
total = 0
for n in numeros:
    if objetivo - n in vistos:
        total += 1
    vistos.add(n)
return total
 
⏱️ unos 1.000 pasos con 300 números
 
La vuelta de tuerca: en vez de buscar el compañero de n, lo calculás (objetivo - n) y preguntás si ya apareció. Como solo mirás hacia atrás, cada pareja se cuenta una sola vez.

Cada vez que escribas un for, preguntate: ¿hay otro for adentro que recorra lo mismo?

forma de saber la respuesta sin volver a mirar todo.
