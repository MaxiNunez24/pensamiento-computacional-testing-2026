## El problema

En la clase anterior el programa cambiaba la página **apenas cargaba**, y listo. Pero lo
interesante es que la página **responda**: que al tocar un botón pase algo, que al escribir en el
buscador se filtren los productos. El programa tiene que **esperar** a que la persona haga algo.

## Escuchar un evento

Cada cosa que hace la persona —un clic, una tecla, escribir en un campo— es un **evento**. Un
programa puede **escuchar** un evento en un elemento, y decir qué hacer cuando pase:

```js
const boton = document.querySelector("#saludar");

boton.addEventListener("click", function () {
  console.log("¡Me tocaron!");
});
```

Se lee: *"al botón, cuando le hagan **click**, hacé esto"*. La función de adentro **no se ejecuta
ahora**: queda guardada, y el navegador la llama **cada vez** que pasa el evento.

:::note[Una función que se pasa sin llamarla]
Es la primera vez que le pasamos **una función entera** a otra, como si fuera un dato. No se llama
con paréntesis: se la damos al navegador para que **él** la llame cuando corresponda. En Python
también se puede (es lo que hace `sorted(lista, key=len)` con `len`), pero en JavaScript lo vas a
ver todo el tiempo.
:::

| Evento | Pasa cuando… |
|---|---|
| `click` | Hacen clic (o tocan, en el celular) |
| `input` | Cambia lo escrito en un campo: **con cada letra** |
| `submit` | Se envía un formulario |
| `keydown` | Se aprieta una tecla |

## Mostrar y ocultar

Con `classList.toggle` y un evento, se arma el "Ver más" de cualquier página: el CSS tiene una clase
`oculto`, y el botón la pone y la saca.

```js
boton.addEventListener("click", function () {
  detalle.classList.toggle("oculto");
});
```

`toggle` devuelve si **quedó puesta** la clase: `true` o `false`. Sirve para cambiar también el
texto del botón.

## El buscador del catálogo

El evento `input` pasa **con cada letra** que se escribe en un campo. Y lo escrito se lee con
`.value`:

```js
const buscador = document.querySelector("#buscar");

buscador.addEventListener("input", function () {
  console.log("Escribieron:", buscador.value);
});
```

Con eso y lo que ya sabés —recorrer, comparar textos, poner y sacar clases—, se arma un buscador.

:::tip[Buscar sin importar mayúsculas]
`"Mate".includes("ma")` es `false`: para JavaScript, `M` y `m` son distintas. Pasá los dos a
minúscula antes de comparar: `.toLowerCase()`, el `.lower()` de Python.
:::

## Formularios: no recargar la página

Un formulario, al enviarse, **recarga la página**: es lo que hacía antes de que existiera
JavaScript, mandando los datos a un servidor. Si querés manejarlo vos, hay que **frenarlo**:

```js
formulario.addEventListener("submit", function (evento) {
  evento.preventDefault();   // "no hagas lo de siempre: no recargues"
  // ...lo tuyo
});
```

La función recibe **el evento**, con información de lo que pasó, y `preventDefault()` le dice al
navegador que no haga lo que hace normalmente. Sin esa línea, la página se recarga y todo lo que tu
programa haya mostrado desaparece en un parpadeo.

<EjercicioWeb

  <input id="email" type="text">
  <button>Suscribirme</button>
</form>
<p id="mensaje"></p>
`}
  js={`// Al enviar el formulario, sin recargar la página:
// - si el correo tiene una @: "¡Gracias! Te vamos a escribir a <el correo>", con la clase ok
// - si no:                    "Revisá el correo: le falta la @", con la clase error
`}

## Para llevar

- Un **evento** es algo que hace la persona: `click`, `input` (cada letra), `submit`, `keydown`.
- `elemento.addEventListener("click", function () { ... })`: la función **queda guardada** y el
  navegador la llama cada vez que pasa.
- Lo que tiene que **durar entre un evento y otro** (una cuenta) vive **afuera** de la función.
- Lo escrito en un campo: `campo.value`, siempre texto.
- `classList.toggle` para mostrar y ocultar, y devuelve si la clase quedó puesta.
- En un formulario: `evento.preventDefault()` para que no recargue la página.
- Para buscar sin importar mayúsculas: `.toLowerCase()` a los dos lados.
