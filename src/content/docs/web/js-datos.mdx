## El problema

Un catálogo de verdad tiene filtros: *"solo los que hay en stock"*, *"de menor a mayor precio"*. Y
algunas cosas se tienen que **recordar**: los favoritos que marcó alguien, el carrito, si eligió el
modo oscuro. Todo eso es trabajar con **listas de objetos**, y guardarlas.

## Filtrar y transformar: `filter` y `map`

En Python, para quedarte con algunos elementos o transformarlos, usás una **comprensión de listas**.
En JavaScript hay dos métodos, uno para cada cosa:

<Tabs>
<TabItem label="🐍 Python">
```python
baratos = [p for p in productos if p["precio"] < 5000]
nombres = [p["nombre"] for p in productos]
```
</TabItem>
<TabItem label="⚡ JavaScript">
```js
const baratos = productos.filter((p) => p.precio < 5000);
const nombres = productos.map((p) => p.nombre);
```
</TabItem>
</Tabs>

| Método | Hace | Devuelve |
|---|---|---|
| `filter(función)` | Se queda con los que **dan `true`** | Una lista **más corta** (o igual) |
| `map(función)` | **Transforma** cada uno | Una lista **del mismo largo** |

Ninguno de los dos cambia la lista original: devuelven una nueva, igual que la comprensión.

### Las funciones flecha

`(p) => p.precio < 5000` es una **función flecha**: una función chiquita, escrita en una línea. Es
lo mismo que:

```js
function (p) {
  return p.precio < 5000;
}
```

A la izquierda de `=>` van los parámetros, y a la derecha **lo que devuelve**. Es el `lambda` de
Python: `lambda p: p["precio"] < 5000`.

## Ordenar: la trampa del `sort`

Ordenar parece fácil, y tiene una trampa famosa:

```js
[100, 25, 3].sort()   // [100, 25, 3]  ← ¡¿qué?!
```

`sort()` sin nada **ordena como si fueran textos**, letra por letra: `"100"` va antes que `"25"`
porque `"1"` va antes que `"2"`. Igual que un diccionario ordena "100" antes que "25".

Para ordenar **números**, hay que decirle cómo comparar dos, con una función:

```js
[100, 25, 3].sort((a, b) => a - b)   // [3, 25, 100]
```

La función recibe dos elementos y devuelve **un número negativo si `a` va antes, positivo si va
después**. `a - b` hace justamente eso con números: de menor a mayor.

:::caution[sort cambia la lista]
A diferencia de `filter` y `map`, **`sort` cambia la lista original**, como el `.sort()` de Python.
Si no querés tocarla, ordená una copia: `[...lista].sort(...)`. Los tres puntos arman una lista
nueva con los mismos elementos.
:::

## JSON: el idioma de los datos

Los datos viajan entre programas —entre tu página y un servidor, entre Python y JavaScript— como
**texto**. El formato que usa todo el mundo es **JSON**, y te va a resultar conocido: es casi igual a
escribir una lista de diccionarios.

```json
[
  { "nombre": "Taza", "precio": 4500 },
  { "nombre": "Mate", "precio": 7800 }
]
```

(Las claves, con comillas dobles siempre.) JavaScript lo convierte en las dos direcciones:

| | De… | A… |
|---|---|---|
| `JSON.stringify(datos)` | una lista u objeto | **texto** JSON |
| `JSON.parse(texto)` | texto JSON | una lista u objeto |

Es lo mismo que `json.dumps` y `json.loads` de Python. Y por eso un programa en Python puede armar un
JSON con los productos, y la página leerlo con JavaScript.

## localStorage: que la página se acuerde

Si recargás la página, **todas las variables se borran**: el programa arranca de cero. Para guardar
algo **en el navegador de esa persona**, que siga ahí mañana, está `localStorage`:

```js
localStorage.setItem("modo", "oscuro");    // guardar
localStorage.getItem("modo");              // leer: "oscuro" (o null si no hay nada)
localStorage.removeItem("modo");           // borrar
```

Guarda **solo texto**. Para guardar una lista, se la pasa a JSON:

```js
const favoritos = ["Mate", "Taza"];
localStorage.setItem("favoritos", JSON.stringify(favoritos));

const leidos = JSON.parse(localStorage.getItem("favoritos"));   // ["Mate", "Taza"]
```

:::note[Es de esa persona, en ese navegador]
Lo que se guarda en `localStorage` **no viaja a ningún lado**: queda en el navegador de quien usa la
página. Sirve para preferencias y favoritos, no para datos que tenga que ver otra persona (eso
necesita un servidor). Es justamente lo que usa esta plataforma para guardar tu avance.

En los ejercicios de acá, `localStorage` está simulado y se borra cada vez que la página se rearma;
en tu página de verdad, dura.
:::

## Para llevar

- `filter` se queda con algunos, `map` transforma todos: las **comprensiones** de Python. Devuelven
  una lista nueva.
- **Funciones flecha**: `(p) => p.precio` es una función que devuelve `p.precio`. El `lambda` de Python.
- `find` devuelve **el primero** que cumple.
- **`sort` ordena como texto**: para números, `sort((a, b) => a - b)`. Y cambia la lista: ordená una
  copia con `[...lista]`.
- **JSON** es el formato de texto de los datos. `JSON.stringify` y `JSON.parse`, como `json.dumps` y
  `json.loads`.
- **`localStorage`** guarda texto en el navegador de esa persona: `setItem`, `getItem` (o `null`),
  `removeItem`. Las listas, pasadas a JSON.
