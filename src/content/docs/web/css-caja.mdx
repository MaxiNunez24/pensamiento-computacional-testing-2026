## El problema

Le pusiste color a todo, pero sigue viéndose apretado: el texto pegado al borde de la tarjeta, las
tarjetas pegadas entre sí, y la página entera estirada de punta a punta en una pantalla ancha. Lo
que falta no es color: es **espacio**. Y para manejar el espacio hay que entender una sola idea.

## Todo es una caja

Para el navegador, **cada elemento es una caja** rectangular, aunque no se vea. Un título, un
párrafo, una imagen, un link: cajas. Y toda caja tiene cuatro capas, de adentro hacia afuera:

```text
┌──────────────── margin (margen) ─────────────────┐
│  ┌───────────── border (borde) ───────────────┐  │
│  │  ┌────────── padding (relleno) ─────────┐  │  │
│  │  │                                      │  │  │
│  │  │      content (el contenido)          │  │  │
│  │  │                                      │  │  │
│  │  └──────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

| Capa | Es… | Tiene color de fondo |
|---|---|---|
| `padding` | El **aire de adentro**, entre el contenido y el borde | ✅ el de la caja |
| `border` | La **línea** alrededor | ✅ el suyo |
| `margin` | El **aire de afuera**, que separa esta caja de las demás | ❌ es transparente |

La pregunta para saber cuál usar: **¿el espacio es parte de la caja, o la separa de las otras?** El
texto lejos del borde de la tarjeta es `padding`; una tarjeta lejos de la otra es `margin`.

```css
.tarjeta {
  padding: 16px;                 /* 16 de aire adentro, en los cuatro lados */
  border: 1px solid #dddddd;     /* grosor, estilo, color */
  border-radius: 12px;           /* las esquinas redondeadas */
  margin-bottom: 20px;           /* 20 de aire abajo, hasta la siguiente */
}
```

Las tres aceptan **un lado solo** (`padding-top`, `margin-left`…) o los cuatro de una. Con dos
valores, el primero es arriba y abajo, y el segundo los costados: `padding: 10px 20px;`.

## Ancho, y cómo centrar

Un párrafo, un título o una tarjeta ocupan **todo el ancho disponible**, aunque su contenido sea
corto. En una pantalla ancha, un texto de punta a punta es incómodo de leer. Se le pone un tope:

```css
.contenedor {
  max-width: 600px;    /* como mucho 600; si la pantalla es más chica, lo que haya */
  margin: 0 auto;      /* 0 arriba y abajo, y AUTO a los costados */
}
```

`margin: auto` a los costados le dice al navegador *"repartí lo que sobra en partes iguales a la
izquierda y a la derecha"*. Resultado: **la caja queda centrada**. Es la forma clásica de centrar
una página.

:::tip[¿`width` o `max-width`?]
`width: 600px` es **exactamente** 600, aunque la pantalla del celular mida 360: se sale. `max-width:
600px` es **como mucho** 600: en la compu mide eso, en el celular se achica. Casi siempre querés
`max-width`.
:::

## El misterio de la caja que se sale

Esto le pasa a todo el mundo la primera vez. Una caja con `width: 100%` que **igual se sale** de su
lugar:

```css
.caja {
  width: 100%;
  padding: 20px;
  border: 4px solid #2f4858;
}
```

¿Por qué? Porque **`width` mide solo el contenido**. El relleno y el borde **se suman afuera**: la
caja mide 100% + 20 + 20 + 4 + 4. Se pasa por 48 píxeles.

La solución es una línea, que cambia cómo se mide:

```css
* {
  box-sizing: border-box;
}
```

Con `border-box`, el ancho **incluye** el relleno y el borde: si decís 100%, mide 100%, y el
relleno se acomoda adentro. Es tan útil que casi todas las páginas lo ponen al principio, para todo
(`*` quiere decir "todos los elementos").

<EjercicioWeb
  titulo="La caja que se sale"
  dificultad="🌿"

  <div class="caja">Esta caja tendría que entrar justo en el marco.</div>
</div>
`}
  css={`body { font-family: system-ui, sans-serif; }

  max-width: 300px;

  pistas={[
    'La caja dice 100%. ¿100% de qué parte de la caja? ¿Qué capas quedan afuera de esa cuenta?',
    '¿Y si en vez de sacarle el relleno, el ancho lo incluyera?',
  ]}
>
La caja dice `width: 100%`, pero se sale del marco punteado. Hacé que entre justo, **sin sacarle
el relleno ni el borde**.

## Cajas en bloque y cajas en línea

No todas las cajas se acomodan igual. Hay dos clases, según su `display`:

| `display` | Se acomodan… | Ejemplos | `width` y `padding` arriba/abajo |
|---|---|---|---|
| `block` | **Una abajo de la otra**, todo el ancho | `<p>`, `<h1>`, `<div>`, `<section>` | ✅ funcionan |
| `inline` | **En el renglón**, como palabras | `<a>`, `<strong>`, `<span>`, `<em>` | ❌ no del todo |
| `inline-block` | En el renglón, **pero** como una caja | — | ✅ funcionan |

Por eso un link no acepta bien un `padding`: es `inline`, va en el renglón como una palabra. Para
hacer un **botón** con un link, se lo pasa a `inline-block`: sigue en el renglón, pero ahora tiene
relleno de verdad.

## Para llevar

- **Todo es una caja**: contenido, `padding` (aire de adentro), `border` (la línea) y `margin` (aire
  de afuera, transparente).
- ¿El espacio es parte de la caja o la separa de otras? `padding` o `margin`.
- `max-width` + `margin: 0 auto` **centra** una caja. `max-width` mejor que `width`: no se sale en
  el celular.
- **`* { box-sizing: border-box; }`** al principio de todo: así el ancho incluye relleno y borde.
- `display`: `block` (uno abajo del otro), `inline` (en el renglón), `inline-block` (en el renglón,
  pero como caja: para los botones).
- `border-radius` redondea las esquinas.
