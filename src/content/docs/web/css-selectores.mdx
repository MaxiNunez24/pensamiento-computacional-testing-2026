## El problema

Las páginas del bloque de HTML funcionan, pero se ven como un documento de 1995: letra con
patitas, todo negro sobre blanco, todo pegado al borde. La de un almacén de barrio que hiciste
quedaría igual que la de un banco.

**CSS** (*Cascading Style Sheets*, hojas de estilo en cascada) es el lenguaje que dice **cómo se ve**
cada cosa. Y lo bueno es que va **aparte** del HTML: podés cambiar toda la apariencia sin tocar el
contenido.

## Una regla de CSS

```css
h1 {
  color: darkgreen;
  font-size: 40px;
}
```

| Parte | Es… |
|---|---|
| `h1` | El **selector**: a qué le aplica |
| `{ ... }` | Las **declaraciones**: qué le cambia |
| `color: darkgreen;` | Una **propiedad** (`color`), dos puntos, un **valor** (`darkgreen`) y punto y coma |

Se lee: *"a todos los `h1`, ponelos verde oscuro y de 40 píxeles"*.

:::caution[El punto y coma]
Cada declaración termina con `;`. Si te lo olvidás, el navegador **no te avisa**: junta esa
declaración con la siguiente, no entiende ninguna de las dos y las ignora. Si algo "no hace nada",
lo primero es mirar los `;` y los `:`.
:::

### ¿Dónde se escribe?

En una página real, el CSS va en **un archivo aparte**, y el HTML lo trae desde el `<head>`:

```html
<head>
  <link rel="stylesheet" href="estilos.css">
</head>
```

Así, **un mismo archivo le da estilo a todas las páginas** del sitio: cambiás un color en un lugar y
cambia en todas. Es lo que hace el catálogo con su `estilos.css`.

## Colores y letras

| Propiedad | Qué cambia | Ejemplo |
|---|---|---|
| `color` | El color del **texto** | `color: #2f4858;` |
| `background-color` | El **fondo** | `background-color: #faf7f2;` |
| `font-family` | La **tipografía** | `font-family: Georgia, serif;` |
| `font-size` | El **tamaño** de letra | `font-size: 20px;` |
| `font-weight` | Negrita | `font-weight: bold;` |
| `text-align` | Alineación | `text-align: center;` |

Los colores se pueden escribir de varias formas:

- **por nombre**: `red`, `darkgreen`, `white` (hay 140);
- **en hexadecimal**: `#2f4858` — rojo, verde y azul, de `00` a `ff`. Es lo que te da cualquier
  selector de colores;
- **en rgb**: `rgb(47, 72, 88)` — lo mismo, de 0 a 255.

`font-family` lleva **una lista**, separada por comas: el navegador usa la primera que tenga
instalada. La última tiene que ser una genérica (`serif`, `sans-serif`, `monospace`), que siempre
existe.

## Elegir qué pintar: los selectores

Con `h1` le aplicás a **todos** los `h1`. Pero en una tienda no querés pintar todos los párrafos
igual: el precio de un producto no es lo mismo que la descripción. Para eso, en el HTML se les pone
**un nombre**, y CSS los busca por ese nombre:

| Selector | Le aplica a… | En el HTML |
|---|---|---|
| `p` | Todos los `<p>` | — |
| `.precio` | Todo lo que tenga **la clase** `precio` | `<span class="precio">` |
| `#portada` | **El** elemento con **id** `portada` (hay uno solo) | `<section id="portada">` |
| `header p` | Los `<p>` que estén **adentro** de un `<header>` | — |

El punto `.` es para las clases y el numeral `#` para los id. Y un elemento puede tener **varias
clases**, separadas por espacios: `class="producto oferta"` es un producto y además está en oferta.

:::tip[¿Clase o id?]
Casi siempre, **clase**. Un id es único y sirve para los links con `#`; una clase se repite tanto
como quieras: todos los precios de la tienda llevan `class="precio"`, y una sola regla los pinta a
todos.
:::

## La cascada: cuando dos reglas se pelean

¿Qué pasa si dos reglas le dicen cosas distintas al mismo elemento?

```css
p { color: gray; }
.oferta { color: red; }
```

El dulce de leche es un `<p>` **y** tiene la clase `oferta`. ¿Gris o rojo? **Rojo**: gana la regla
**más específica**. El orden es:

| Selector | Específico | Gana sobre… |
|---|---|---|
| `#id` | 🥇 Muy | Todo lo de abajo |
| `.clase` | 🥈 Bastante | Las etiquetas |
| `etiqueta` | 🥉 Poco | — |

Cuando un selector combina varias cosas, **se cuentan**: primero los id, después las clases, y
recién después las etiquetas. `main .producto` tiene una clase **y** una etiqueta, así que le gana
a `.oferta`, que tiene una clase sola. Pero ojo: **una clase le gana a cualquier cantidad de
etiquetas**. `main p` (dos etiquetas) pierde contra `.oferta`, porque las clases se comparan antes.

Y si dos reglas son **igual** de específicas, gana **la que está más abajo** en el CSS. Por eso se
llama *cascada*: las reglas caen una sobre otra, y la que queda arriba es la que se ve.

:::note[La herencia]
Algunas propiedades **se heredan**: si le ponés `font-family` al `<body>`, todo lo de adentro la
toma, sin que tengas que repetirla en cada etiqueta. Pasa con las del texto (`color`, `font-family`,
`font-size`), no con las de la caja (`background-color`, el borde, los márgenes).
:::

## Para llevar

- Una **regla**: `selector { propiedad: valor; }`. Cada declaración con su `:` y su `;`.
- En una página real, el CSS va en un archivo aparte: `<link rel="stylesheet" href="estilos.css">`.
- **Selectores**: `etiqueta`, `.clase`, `#id`, y `padre hijo` para lo que está adentro.
- Colores por nombre, `#hex` o `rgb()`. `font-family` con una lista que termina en una genérica.
- **La cascada**: gana la regla más específica (`#id` > `.clase` > `etiqueta`); si empatan, la de
  más abajo.
- Las propiedades del **texto se heredan**: dásela al `<body>` y la toma todo.
