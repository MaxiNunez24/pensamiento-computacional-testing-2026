## El problema

El catálogo dice qué productos hay, pero no cuáles **se agotaron**. Los precios están escritos a
mano en el HTML. Y si mañana agregás un producto, hay que copiar y pegar una tarjeta entera. Todo
eso lo puede hacer un programa: **leer la página, cambiarla y agregarle cosas**.

## El DOM: la página como objetos

Cuando el navegador lee tu HTML, arma en memoria **un árbol de objetos**, uno por cada etiqueta. Ese
árbol se llama **DOM** (*Document Object Model*), y JavaScript lo puede leer y cambiar. Cada cambio
**se ve al instante** en la página.

```text
document
└── html
    ├── head
    │   └── title
    └── body
        ├── h1
        └── ul
            ├── li
            └── li
```

Todo arranca de `document`, que es la página entera.

## Encontrar un elemento

Para buscar, se usan **los mismos selectores de CSS**:

```js
const titulo = document.querySelector("h1");            // el primero que encuentre
const precio = document.querySelector("#precio-mate");  // por id
const productos = document.querySelectorAll(".producto"); // TODOS: una lista
```

| | Devuelve |
|---|---|
| `querySelector(selector)` | **El primero** que coincide, o `null` si no hay ninguno |
| `querySelectorAll(selector)` | **Todos**, en una lista que se recorre con `for ... of` |

## Cambiar lo que dice

```js
const titulo = document.querySelector("h1");
titulo.textContent = "Almacén Don Pepe";
```

`textContent` es **el texto de adentro**: se lee y se cambia. Es como si el programa entrara al HTML
y escribiera ahí.

## Cambiar las clases

Muchas veces no querés cambiar el texto sino **cómo se ve**. La forma prolija es **no tocar el CSS
desde JavaScript**: el CSS ya tiene una clase preparada, y el programa se la pone o se la saca.

```js
const mate = document.querySelector("#mate");
mate.classList.add("agotado");      // le pone la clase
mate.classList.remove("agotado");   // se la saca
mate.classList.toggle("agotado");   // si la tiene, se la saca; si no, se la pone
```

Así cada lenguaje hace lo suyo: **CSS dice cómo se ve un agotado, JavaScript decide cuál está
agotado**.

### Datos guardados en el HTML

Un elemento puede llevar **datos propios**, en atributos que empiezan con `data-`:

```html
<div class="producto" data-stock="0">Dulce de leche</div>
```

Y JavaScript los lee con `dataset`, sin el `data-`:

```js
elemento.dataset.stock    // "0"  ← siempre texto, como el input() de Python
```

## Crear elementos nuevos

Lo más útil: **armar la página desde los datos**, igual que hiciste con Python en el catálogo. Un
elemento nuevo se crea, se completa y se agrega:

```js
const lista = document.querySelector("#lista");

const item = document.createElement("li");   // 1. crear un <li> (todavía no está en la página)
item.textContent = "Yerba";                  // 2. completarlo
lista.append(item);                          // 3. agregarlo adentro de la lista: ahora se ve
```

Y con un `for`, uno por cada dato:

```js
const compras = ["Yerba", "Azúcar", "Pan"];
for (const cosa of compras) {
  const item = document.createElement("li");
  item.textContent = cosa;
  lista.append(item);
}
```

## Armar pedazos de HTML de una

Para algo más grande que un `<li>` —una tarjeta con título, precio y botón—, crear cada elemento por
separado es largo. Se puede escribir **el HTML entero en una template string** y meterlo con
`innerHTML`:

```js
const catalogo = document.querySelector(".catalogo");
for (const p of PRODUCTOS) {
  catalogo.innerHTML += `
    <article class="tarjeta">
      <h2>${p.nombre}</h2>
      <p>$ ${p.precio}</p>
    </article>`;
}
```

Es **exactamente** lo que hiciste con el f-string de Python en el catálogo: un texto con huecos para
los datos.

:::danger[innerHTML, solo con datos tuyos]
`innerHTML` **interpreta** el texto como HTML. Si el texto viene de alguien de afuera —lo que
escribió una persona en un formulario—, puede meter un `<script>` y correr su programa en tu página.
Para mostrar lo que escribe la gente, **`textContent`**, que lo muestra tal cual, sin interpretarlo.
:::

## Para llevar

- El **DOM** es la página como un árbol de objetos. Arranca en `document`.
- `document.querySelector(selector)` → el primero (o `null`); `querySelectorAll` → todos.
  **Los mismos selectores de CSS.**
- `.textContent` lee y cambia el texto.
- `.classList.add / remove / toggle`: el CSS define la clase, JavaScript la pone o la saca.
- `data-algo` en el HTML se lee con `.dataset.algo`, y **siempre es texto**.
- Crear: `document.createElement("li")`, completarlo, y `.append()` adentro de otro.
- `innerHTML` con una template string arma HTML de una, **pero solo con datos tuyos**. Lo que escribe
  la gente, con `textContent`.
