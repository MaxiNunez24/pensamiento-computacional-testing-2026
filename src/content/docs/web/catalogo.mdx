## El problema

Esta clase salió de una pregunta real. Alguien que vende productos quiere lo que tienen muchos
emprendimientos: **un catálogo en internet**, con una tarjeta por producto, el precio, y un botón
que abre WhatsApp con el mensaje ya escrito. Y la pregunta que vino detrás fue:

> *"¿Y lo que están aprendiendo, para qué sirve? ¿Todavía no saben hacer nada útil?"*

Hagamos la cuenta. Los productos están en una **planilla**. Para armar el catálogo hay que:

| Paso | ¿Lo sabés hacer? |
|---|---|
| Leer la planilla | ✅ Lo hiciste con el bot del SiGeS: `csv.DictReader` |
| Recorrer los productos, uno por uno | ✅ Un `for` |
| Armar el texto de cada tarjeta con los datos | ✅ Un f-string |
| Guardar el resultado en un archivo | ✅ `with open(..., "w")` |
| Que el resultado sea una **página web** | ❌ Esto es lo nuevo |
| Publicarla con un link | 🟡 Casi: ya subís cosas a GitHub |

La parte difícil —**leer los datos, recorrerlos y decidir qué mostrar**— ya la sabés. Lo que
falta es el idioma de las páginas web. Y es lo más fácil de todo.

:::note[La analogía de la clase]
**HTML y CSS son la ropa. La lógica es el cuerpo.** Una página escrita a mano se ve igual de linda,
pero si cambia un precio, alguien la tiene que editar a mano; si agregás un producto, a mano. La
que arma Python se actualiza sola: cambiás la planilla, corrés el programa, y está.
:::

## Una página es un archivo de texto

Una página web es **un archivo de texto** que termina en `.html`. Adentro, el contenido va entre
**etiquetas** que le dicen al navegador qué es cada cosa:

```html
<h2>Mate de calabaza</h2>
<p>Curado y listo para usar.</p>
```

- `<h2>` abre un **título**, y `</h2>` lo cierra. Lo de adentro es el texto del título.
- `<p>` es un **párrafo**.
- Casi todas las etiquetas se abren y se cierran: la de cierre es igual, con una `/`.

Y una etiqueta puede llevar **atributos**, que van adentro de la de apertura:

```html
<p class="precio">$ 7800</p>
```

`class="precio"` no se ve en la página: es un **nombre** que le ponemos a ese párrafo, para que los
estilos sepan cuál es el precio y lo pinten grande y en negrita.

Una tarjeta entera es esto: una caja (`<article>`) con cosas adentro.

```html
<article class="producto">
  <div class="producto__foto">🧉</div>
  <h2>Mate de calabaza</h2>
  <p class="precio">$ 7800</p>
</article>
```

Fijate en la **sangría**: lo que está adentro del `<article>` va corrido a la derecha. Al
navegador le da igual (no es Python), pero a vos te deja ver qué está adentro de qué.

### Un link

Los links son la etiqueta `<a>`, y adónde llevan va en el atributo `href`:

```html
<a href="https://www.google.com">Ir a Google</a>
```

Para WhatsApp hay una dirección especial, que abre un chat con ese número:

```text
https://wa.me/5492215550000
```

El número va **sin `+`, sin espacios y sin guiones**: `54` (Argentina) + `9` (celular) + la
característica **sin el 0** + el número **sin el 15**. Un 221 15 555-0000 de La Plata queda
`5492215550000`.

## Que lo escriba Python

Ahora viene lo tuyo. Una tarjeta es **un texto**, y vos ya sabés armar textos con los datos
adentro: un f-string.

Lo único nuevo: el texto de una tarjeta tiene **varios renglones**. Para eso, el string va entre
**tres comillas**:

```python
nombre = "Vela aromática"
html = f"""
<article class="producto">
  <h2>{nombre}</h2>
</article>
"""
```

:::caution[Las comillas adentro de las llaves]
Si el dato sale de un diccionario, adentro de las llaves usá **comillas simples**:
`{producto['nombre']}`. Con dobles, en un Python anterior al 3.12 se confunde con el final del
string y da error.
:::

## El botón de WhatsApp, con el mensaje ya escrito

El link de WhatsApp puede llevar **el mensaje ya escrito**, para que la persona solo toque enviar:

```text
https://wa.me/5492215550000?text=Hola, quiero consultar por: Mate de calabaza
```

Pero un link **no puede tener espacios**, ni tildes, ni comas sueltas. Hay que "traducir" el
mensaje al idioma de los links: cada espacio pasa a ser `%20`, la `á` pasa a `%C3%A1`… A mano es
imposible. Python lo hace solo.

:::note[📦 Módulo: urllib.parse]
Viene con Python: no hay que instalar nada. De todo lo que tiene, usamos una sola función.

```python
from urllib.parse import quote

quote("Hola, quiero consultar por: Mate de calabaza")
# 'Hola%2C%20quiero%20consultar%20por%3A%20Mate%20de%20calabaza'
```

| Función | Qué hace |
|---|---|
| `quote(texto)` | Devuelve el texto listo para ir adentro de un link |

`from urllib.parse import quote` trae **solo** esa función, y por eso después se usa sin el
`urllib.parse.` adelante.
:::

## La página entera

Una página completa tiene, además de las tarjetas, una **cabecera** con datos para el navegador
(el título de la pestaña, que la letra se vea bien en el celular, de dónde sacar los estilos) y el
**cuerpo**, que es lo que se ve:

```html
<!doctype html>
<html lang="es">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi catálogo</title>
  <link rel="stylesheet" href="estilos.css">
</head>
<body>
  <header class="encabezado"><h1>Mi catálogo</h1></header>
  <main class="catalogo">
    ...las tarjetas...
  </main>
</body>
</html>
```

No hace falta aprenderla de memoria: es siempre igual, y la vas a copiar. Lo que importa es saber
**dónde van las tarjetas**: adentro del `<main>`.

## Publicarlo en internet, gratis

GitHub publica páginas gratis: se llama **GitHub Pages**, y es justamente donde está publicada esta
plataforma.

1. En GitHub, creá un repositorio nuevo **público**, por ejemplo `catalogo`.
2. Subí `index.html` y `estilos.css`. Con lo de Git que ya sabés (`git add`, `git commit`,
   `git push`), o arrastrándolos en la página del repositorio, con **Add file → Upload files**.
3. En el repositorio: **Settings → Pages**. En *Branch* elegí `main` y la carpeta `/ (root)`, y
   tocá **Save**.
4. Esperá uno o dos minutos y recargá esa página: arriba aparece el link, algo así como
   `https://tu-usuario.github.io/catalogo/`.

**Ese link es tu catálogo.** Se puede mandar por WhatsApp, poner en Instagram o imprimir en un QR.
Cada vez que generes la página de nuevo, la volvés a subir y el link muestra la versión nueva.

:::caution[Lo que se sube es público]
Cualquiera con el link ve la página, y el repositorio también. Ahí no van datos que no pondrías en
una vidriera: tu número de WhatsApp sí (es para que te escriban), una dirección particular no.
:::

## Desafío: con fotos de verdad

Los emojis sirven para practicar, pero un catálogo de verdad lleva fotos. Para eso:

1. Una carpeta `fotos/` al lado de `index.html`, con una foto por producto.
2. Una columna más en la planilla, `foto`, con el nombre del archivo: `taza.jpg`.
3. En `tarjeta()`, en vez de la caja del emoji, una **imagen**:

```html
<img class="producto__foto" src="fotos/taza.jpg" alt="Taza de cerámica">
```

`<img>` es de las pocas etiquetas **que no se cierran**: no tiene contenido, solo atributos. `src`
dice qué archivo mostrar, y `alt` lo describe para quien no puede ver la imagen. Los estilos ya
están preparados para que la foto ocupe el ancho de la tarjeta.

¿Y si un producto todavía no tiene foto? Que siga con el emoji. Eso es un `if`: ya sabés.

Y para subirlo, la carpeta `fotos/` va también al repositorio.

## Para llevar

- **Una página web es un archivo de texto** con etiquetas: `<h2>` título, `<p>` párrafo, `<a href>`
  link, `<img src>` imagen. Casi todas se abren y se cierran.
- **HTML dice qué es cada cosa, CSS cómo se ve, y Python la arma con los datos.** Por eso se
  actualiza sola: los datos viven en la planilla.
- Un **f-string de tres comillas** arma un texto de varios renglones con los datos adentro.
- `quote()` deja un texto listo para ir adentro de un link.
- **GitHub Pages** publica gratis lo que subas a un repositorio. `index.html` es la página que
  abre la dirección.
