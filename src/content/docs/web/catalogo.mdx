## El problema

Esta clase salió de una pregunta real. Alguien que vende productos quiere lo que tienen muchos
emprendimientos: **un catálogo en internet**, con una tarjeta por producto, el precio, y un botón
que abre WhatsApp con el mensaje ya escrito. Y la pregunta que vino detrás fue:

> *"¿Y lo que están aprendiendo, para qué sirve? ¿Todavía no saben hacer nada útil?"*

Hagamos la cuenta. Los productos están en una **planilla**. Para armar el catálogo hay que:

| Paso | ¿Lo sabés hacer? |
|---|---|
| Leer la planilla | ✅ Lo hiciste con el bot del SiGeS: `csv.DictReader` |
| Recorrer los productos, uno por uno | ✅ Un `for` |
| Armar el texto de cada tarjeta con los datos | ✅ Un f-string |
| Guardar el resultado en un archivo | ✅ `with open(..., "w")` |
| Que el resultado sea una **página web** | ❌ Esto es lo nuevo |
| Publicarla con un link | 🟡 Casi: ya subís cosas a GitHub |

La parte difícil —**leer los datos, recorrerlos y decidir qué mostrar**— ya la sabés. Lo que
falta es el idioma de las páginas web. Y es lo más fácil de todo.

:::note[La analogía de la clase]
**HTML y CSS son la ropa. La lógica es el cuerpo.** Una página escrita a mano se ve igual de linda,
pero si cambia un precio, alguien la tiene que editar a mano; si agregás un producto, a mano. La
que arma Python se actualiza sola: cambiás la planilla, corrés el programa, y está.
:::

El **look** también salió de un caso real: un catálogo que un emprendimiento armó en Canva, con
fondo gris rosado, fotos recortadas en círculo, el precio en una píldora verde y ramitas de hojas en
las esquinas. Los estilos de esta clase lo copian. La diferencia es que en Canva cada página se
arma a mano, y acá se arma sola.

## Una página es un archivo de texto

Una página web es **un archivo de texto** que termina en `.html`. Adentro, el contenido va entre
**etiquetas** que le dicen al navegador qué es cada cosa:

```html
<h2>Mate de calabaza</h2>
<p>Curado y listo para usar.</p>
```

- `<h2>` abre un **título**, y `</h2>` lo cierra. Lo de adentro es el texto del título.
- `<p>` es un **párrafo**.
- Casi todas las etiquetas se abren y se cierran: la de cierre es igual, con una `/`.

Y una etiqueta puede llevar **atributos**, que van adentro de la de apertura:

```html
<p class="precio">$ 7800</p>
```

`class="precio"` no se ve en la página: es un **nombre** que le ponemos a ese párrafo, para que los
estilos sepan cuál es el precio y lo pinten grande y en negrita.

Una tarjeta entera es esto: una caja (`<article>`) con cosas adentro.

```html
<article class="producto">
    <div class="producto__foto">🧉</div>
    <h2>Mate de calabaza</h2>
    <p class="precio">$ 7800</p>
</article>
```

Fijate en la **sangría**: lo que está adentro del `<article>` va corrido a la derecha. Al
navegador le da igual (no es Python), pero a vos te deja ver qué está adentro de qué.

### Un link

Los links son la etiqueta `<a>`, y adónde llevan va en el atributo `href`:

```html
<a href="https://www.google.com">Ir a Google</a>
```

Para WhatsApp hay una dirección especial, que abre un chat con ese número:

```text
https://wa.me/5492215550000
```

El número va **sin `+`, sin espacios y sin guiones**: `54` (Argentina) + `9` (celular) + la
característica **sin el 0** + el número **sin el 15**. Un 221 15 555-0000 de La Plata queda
`5492215550000`.

## Que lo escriba Python

Ahora viene lo tuyo. Una tarjeta es **un texto**, y vos ya sabés armar textos con los datos
adentro: un f-string.

Lo único nuevo: el texto de una tarjeta tiene **varios renglones**. Para eso, el string va entre
**tres comillas**:

```python
nombre = "Vela aromática"
html = f"""
<article class="producto">
    <h2>{nombre}</h2>
</article>
"""
```

:::caution[Las comillas adentro de las llaves]
Si el dato sale de un diccionario, adentro de las llaves usá **comillas simples**:
`{producto['nombre']}`. Con dobles, en un Python anterior al 3.12 se confunde con el final del
string y da error.
:::

## El precio, siempre igual

En el catálogo de Canva del que salió el estilo, los precios estaban escritos a mano, y se
desparejaron: `$7.900`, `$12,000`, `$10,000`. Unos con punto y otros con coma. Pasa siempre que algo
se escribe a mano muchas veces.

Con Python, en la planilla va **solo el número** (`12500`) y el formato lo pone el programa. Sale
igual en todos los productos, porque lo escribe una sola función.

Para separar los miles, un f-string tiene un truco: `:,` después del valor.

```python
f"{12500:,}"     # '12,500'
```

Dos detalles. Separa con **coma**, como en inglés, y acá usamos punto. Y solo funciona con
**números**: lo que viene de la planilla es texto, aunque tenga cifras.

## El botón de WhatsApp, con el mensaje ya escrito

El link de WhatsApp puede llevar **el mensaje ya escrito**, para que la persona solo toque enviar:

```text
https://wa.me/5492215550000?text=Hola, quiero consultar por: Mate de calabaza
```

Pero un link **no puede tener espacios**, ni tildes, ni comas sueltas. Hay que "traducir" el
mensaje al idioma de los links: cada espacio pasa a ser `%20`, la `á` pasa a `%C3%A1`… A mano es
imposible. Python lo hace solo.

:::note[📦 Módulo: urllib.parse]
Viene con Python: no hay que instalar nada. De todo lo que tiene, usamos una sola función.

```python
from urllib.parse import quote

quote("Hola, quiero consultar por: Mate de calabaza")
# 'Hola%2C%20quiero%20consultar%20por%3A%20Mate%20de%20calabaza'
```

| Función | Qué hace |
|---|---|
| `quote(texto)` | Devuelve el texto listo para ir adentro de un link |

`from urllib.parse import quote` trae **solo** esa función, y por eso después se usa sin el
`urllib.parse.` adelante.
:::

## Con fotos de verdad

Los emojis sirven para practicar, pero un catálogo de verdad lleva fotos. Para eso:

1. Una carpeta `fotos/` al lado de la página, con una foto por producto.
2. Una columna más en la planilla, `foto`, con el nombre del archivo: `taza.jpg`.
3. En la tarjeta, en vez de la caja del emoji, una **imagen**:

```html
<img class="producto__foto" src="fotos/taza.jpg" alt="Taza de cerámica">
```

`<img>` es de las pocas etiquetas **que no se cierran**: no tiene contenido, solo atributos. `src`

recortan en círculo.

si la clave no está, devuelve `None` en vez de dar error.

```python

{"nombre": "Bolso matero", "emoji": "👜", "foto": ""}               # celda vacía
{"nombre": "Yerbera", "emoji": "🫙"}                                # sin la clave
```

## La página entera

Una página completa tiene, además de las tarjetas, una **cabecera** con datos para el navegador
(el título de la pestaña, que la letra se vea bien en el celular, de dónde sacar los estilos) y el
**cuerpo**, que es lo que se ve: arriba el nombre de la marca, en el medio los productos y abajo,
como la última página del catálogo de Canva, cómo contactarte.

```html
<!doctype html>
<html lang="es">
<head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Mi catálogo</title>
    <link rel="stylesheet" href="estilos.css">
</head>
<body>
    <header class="encabezado"><h1>Mi catálogo</h1></header>
    <main class="catalogo">
        ...las tarjetas...
    </main>
    <footer class="contacto">
        <h2>¡Contactá conmigo!</h2>
        <a class="consultar" href="https://wa.me/5492215550000">Escribime por WhatsApp</a>
        <p>Tu consulta no es molestia</p>
    </footer>
</body>
</html>
```

## Hacerlo tuyo

El programa ya está terminado. Para que el catálogo sea el de tu emprendimiento **no se toca más
código**: se cambian datos.

| Quiero cambiar… | Dónde |
|---|---|
| El nombre de la marca | `TITULO`, arriba de todo en `catalogo.py` |
| El número de WhatsApp | `NUMERO`, ahí mismo |
| Los productos, los precios, las descripciones | `productos.csv` |
| Las fotos | La carpeta `fotos/`, y su nombre en la columna `foto` de la planilla |
| Los colores y la letra | Las variables de arriba de `estilos.css` (ver [Que se vea como tu marca](#que-se-vea-como-tu-marca)) |

La planilla se puede abrir con una planilla de cálculo (al guardar, elegí **CSV UTF-8**) o con un
editor de texto como VS Code. Así queda una fila:

```text
nombre,precio,emoji,foto,descripcion
Taza de cerámica,4500,☕,taza.svg,Pintada a mano. Va al microondas.
```

- **El precio, solo el número**: `7900`, sin `$` ni puntos. El formato lo pone `precio()`.
- **La foto**, el nombre del archivo que pusiste en `fotos/`. Si la dejás vacía, sale el emoji.
- **No borres la primera línea**: son los nombres de las columnas.

:::caution[Las fotos: tres cosas que en tu compu andan y publicadas no]
- **El nombre, exactamente igual** en la planilla y en el archivo, mayúsculas incluidas. En Windows
  `Taza.JPG` y `taza.jpg` son lo mismo; en GitHub Pages no, y la foto no aparece.
- **Sin espacios ni tildes** en el nombre del archivo: `conjunto-negro.jpg`, no `Conjunto negro.jpg`.
- **Livianas.** Una foto del celular pesa 3 o 4 MB, y con datos móviles el catálogo tarda en abrir.
  Achicala a unos 800 píxeles de ancho: con cualquier editor de fotos, o en
  [squoosh.app](https://squoosh.app), gratis y desde el navegador.

Y como se recortan en círculo, conviene que sean **cuadradas**, con el producto en el medio.
:::

¿Querés sumar tu Instagram? En `pagina()`, abajo del botón de WhatsApp del final, un link más:

```html
<a class="consultar" href="https://instagram.com/tu_usuario">Instagram</a>
```

:::tip[Cada vez que cambie algo]
¿Cambió un precio? ¿Llegó un producto nuevo? Editás la planilla (y sumás la foto) y volvés a correr
`python catalogo.py`. **Nunca tocás el HTML a mano.** Para eso lo armó Python.
:::

## Más datos de cada producto (optativo)

Cada emprendimiento tiene sus datos. Si hacés impresión 3D, importa el **material** y las
**medidas**; si tejés, los **talles**; si cocinás, el **tiempo de entrega**. No hay una lista que le
sirva a todos. Lo que sí se puede hacer es dejar que la planilla tenga **las columnas que vos
quieras**, y que cada una aparezca en la tarjeta:

```text
nombre,precio,emoji,foto,descripcion,material,medidas
Maceta geométrica,6500,🪴,,Impresa en 3D.,PLA biodegradable,10 x 10 x 12 cm
```

Pero entonces la función que arma esos renglones **no sabe qué datos le van a llegar**, ni cuántos.
Para eso está lo que viste en [Funciones II](../../clases/funciones-2/#kwargs-lo-mismo-pero-con-nombre):
**`**kwargs`**, que junta **todos los datos con nombre** que le pasen en un diccionario.

```python
def detalles(**datos):
    print(datos)

detalles(material="PLA", medidas="10 x 10 cm")   # {'material': 'PLA', 'medidas': '10 x 10 cm'}
detalles()                                       # {}
```

Y al revés: si ya tenés un diccionario, `**` lo **desarma** en datos con nombre al llamar a la
función. Estas dos líneas hacen lo mismo:

```python
detalles(material="PLA", medidas="10 x 10 cm")
detalles(**{"material": "PLA", "medidas": "10 x 10 cm"})
```

Así la tarjeta le puede pasar a `detalles()` **las columnas de más de cada producto**, sean las que
sean. `extras(producto)` (ya está hecha) se queda con las columnas que no son las de siempre, y
la tarjeta la llama así: `{detalles(**extras(producto))}`.

## Publicarlo en internet, gratis

GitHub publica páginas gratis: se llama **GitHub Pages**, y es justamente donde está publicada esta
plataforma.

1. En GitHub, creá un repositorio nuevo **público**, por ejemplo `catalogo`.
2. Subí **todo lo que hay en la carpeta `catalogo/`**: `index.html`, `estilos.css` y las carpetas
   `fotos/` y `adornos/`. Con lo de Git que ya sabés (`git add`, `git commit`, `git push`), o en la
   página del repositorio con **Add file → Upload files**: ahí se pueden arrastrar las carpetas
   enteras.
3. En el repositorio: **Settings → Pages**. En *Branch* elegí `main` y la carpeta `/ (root)`, y
   tocá **Save**.
4. Esperá uno o dos minutos y recargá esa página: arriba aparece el link, algo así como
   `https://tu-usuario.github.io/catalogo/`.

**Ese link es tu catálogo.** Se puede mandar por WhatsApp, poner en la bio de Instagram o imprimir
en un QR.

Para actualizarlo, generás la página de nuevo y subís `index.html` (y las fotos nuevas, si hay).
Un archivo que se sube con el mismo nombre **reemplaza** al anterior. En uno o dos minutos, el link
muestra la versión nueva.

:::caution[Lo que se sube es público]
Cualquiera con el link ve la página, y el repositorio también. Ahí no van datos que no pondrías en
una vidriera: tu número de WhatsApp sí (es para que te escriban), una dirección particular no.
:::

## Que se vea como tu marca

Los colores y las letras están **una sola vez**, arriba de todo en `estilos.css`, como
**variables**:

```css
:root {
    --fondo: #d3cac8;
    --texto: #5b6844;
    --acento: #5f6f45;
    --linea: #93a77c;
    --marca: #ffffff;
    --fondo-foto: #ecd3dc;
    ...
}
```

El resto de los estilos no dice "verde": dice `var(--acento)`. Así que cambiando **un valor**,
cambia en todas las partes donde se usa. Es la misma idea que una variable de Python, y está
explicada en <a href={b + 'web/css-responsive/#variables-de-css'}>CSS IV · Variables de CSS</a>.

| Variable | Qué pinta |
|---|---|
| `--fondo` | El fondo de toda la página |
| `--texto` | Los nombres y las descripciones |
| `--acento` | La píldora del precio y los botones |
| `--linea` | La línea arriba de cada nombre, y las ramitas verdes |
| `--marca` | El nombre de la marca y el "¡Contactá conmigo!" |
| `--fondo-foto` | El círculo de los productos que no tienen foto |

Los colores se escriben con un `#` y seis cifras. Para encontrar el de un color que te gusta,
buscá **"color picker"** en Google: aparece una paleta que te da el código.

## Para llevar

- **Una página web es un archivo de texto** con etiquetas: `<h2>` título, `<p>` párrafo, `<a href>`
  link, `<img src>` imagen. Casi todas se abren y se cierran.
- **Lo que se repite, lo escribe una función**: por eso los precios salen todos iguales, y un
  producto sin foto sigue con su emoji sin que nadie se acuerde.
- **HTML dice qué es cada cosa, CSS cómo se ve, y Python la arma con los datos.** Por eso se
  actualiza sola: los datos viven en la planilla.
- Un **f-string de tres comillas** arma un texto de varios renglones con los datos adentro.
- `quote()` deja un texto listo para ir adentro de un link.
- **GitHub Pages** publica gratis lo que subas a un repositorio. `index.html` es la página que
  abre la dirección.
- **Los colores y las letras de la marca** están en las variables de arriba de `estilos.css`:
  cambiar el estilo entero es cambiar esos valores.

Esto es lo justo para el catálogo. HTML, CSS y JavaScript dan para mucho más —que la página se vea

para este mismo catálogo.
