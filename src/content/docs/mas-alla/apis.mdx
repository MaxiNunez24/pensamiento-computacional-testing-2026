## El problema

Tu programa sabe solamente lo que vos le escribiste. Si querés que diga **cuándo es el próximo
feriado** o muestre **el dólar de hoy**,
tendrías que cambiar el número a mano todas las mañanas. Y si querés una foto distinta cada vez
que tocás un botón, tendrías que tener miles de fotos guardadas.

Esos datos ya existen, actualizados, **en otras computadoras**. Lo que falta es que tu programa
se los pueda **pedir**. Para eso están las **APIs**.

## Qué es una API

Una **API** es una dirección de internet que, en vez de devolverte una página para mirar, te
devuelve **datos** para que los use tu programa.

Pensalo como un mozo: vos no entrás a la cocina, le hacés **un pedido** y te trae **una
respuesta**. No te importa cómo la cocinaron.

### Probalo en el navegador

Abrí esta dirección en una pestaña nueva:
[https://dog.ceo/api/breeds/image/random](https://dog.ceo/api/breeds/image/random)

Vas a ver algo así:

```json
{"message": "https://images.dog.ceo/breeds/beagle/n02088364_16689.jpg", "status": "success"}
```

Recargá la página: el link cambia. Cada pedido te devuelve **un perro al azar**.

Eso que ves es **JSON**, el idioma en que se mandan datos las computadoras. Y fijate que se
parece muchísimo a algo que ya conocés: **es un diccionario de Python**, con sus llaves, sus
claves y sus valores. Si viste la optativa de <a href={b + 'clases/json/'}>JSON</a>, ya lo
conocés; si no, alcanza con saber diccionarios y listas.

## Preparar VS Code

Esta vez sí hay que instalar algo: **`requests`**, la librería que hace los pedidos, y
**`pillow`**, que vamos a usar al final para mostrar las fotos en una ventana.

1. Creá una carpeta nueva, por ejemplo `apis`, y abrila con **File → Open Folder**.
2. Abrí la terminal (**Terminal → New Terminal**) y armá un **entorno virtual**, como hicimos con
   <a href={b + 'clases/bot-siges/#el-entorno-virtual'}>el bot del SiGeS</a>:

   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```

   La línea de la terminal tiene que empezar con **`(.venv)`**.
3. Con el `(.venv)` a la vista, instalá las dos librerías:

   ```bash
   pip install requests pillow
   ```

4. Creá un archivo `perros.py`. Lo ejecutás con el **▶** de arriba a la derecha.

:::caution[Si dice que "la ejecución de scripts está deshabilitada"]
Es PowerShell, que por seguridad no deja correr el archivo de activación. No hace falta cambiar
nada de la compu: en la terminal, tocá la flechita al lado del **+** y elegí **Command Prompt**.
Ahí `.venv\Scripts\activate` anda sin problema.
:::

:::note[Si dice `ModuleNotFoundError: No module named 'requests'`]
El ▶ está usando el Python de la compu y no el del entorno virtual, que es donde instalaste

## Tu primer pedido

```python
import requests

respuesta = requests.get("https://dog.ceo/api/breeds/image/random", timeout=10)
print(respuesta.status_code)

datos = respuesta.json()
print(datos)
print(datos["message"])
```

Ejecutalo un par de veces: cada vez sale un link distinto. Copialo en el navegador y ves el
perro.

| Línea | Qué hace |
|---|---|
| `requests.get(dirección, timeout=10)` | Hace el pedido. `timeout=10` quiere decir: si en 10 segundos no contesta, rendite |
| `respuesta.status_code` | Un número que dice cómo salió el pedido |
| `respuesta.json()` | Convierte el JSON de la respuesta en diccionarios y listas de Python |

Los números de `status_code` más comunes:

| Código | Qué quiere decir |
|---|---|
| **200** | Salió bien |
| **404** | Eso que pediste no existe |
| **500** | Se rompió algo del otro lado: no es culpa tuya |

## Cuando algo sale mal

Hay dos cosas distintas que pueden fallar:

1. **El pedido llega, pero lo que pediste no existe.** Por ejemplo, una raza que no conocen. La
   respuesta llega igual, con `status_code` **404**.
2. **El pedido ni siquiera llega:** no hay internet, o el servidor no contesta. Ahí `requests`
   tira una **excepción**, y si no la atrapás, el programa se corta.

Las dos se atienden distinto. La primera con un `if` y la segunda con `try` / `except`, como en
<a href={b + 'clases/excepciones/'}>la clase de Excepciones</a>:

```python
import requests

raza = input("¿Qué raza? (en inglés, por ejemplo beagle): ").lower()
url = f"https://dog.ceo/api/breed/{raza}/images/random"

try:
    respuesta = requests.get(url, timeout=10)
    if respuesta.status_code == 200:
        print("Tu perro:", respuesta.json()["message"])
    else:
        print(f"No conozco la raza {raza}.")
except requests.exceptions.RequestException:
    print("No me pude conectar. ¿Tenés internet?")
```

`requests.exceptions.RequestException` atrapa **todos** los errores de conexión: sin internet,
servidor caído, demasiada demora.

**Probá:** `beagle`, `pug`, `husky`, y después una que no exista, como `firulais`. Y si te animás,
desconectá el WiFi y probá de nuevo.

## ArgentinaDatos: los datos del país

[ArgentinaDatos](https://argentinadatos.com/) es una API argentina, **gratis y sin registrarse**,
que junta en un solo lugar un montón de datos públicos: feriados, cotizaciones del dólar,
inflación, riesgo país, tasas de plazo fijo. Todas sus direcciones empiezan igual,
`https://api.argentinadatos.com/v1/`, y lo que cambia es el final. La lista completa está en
[su documentación](https://argentinadatos.com/docs/).

Arrancamos por lo más cercano: **los feriados**.

### Arrancamos con los feriados

Abrí [https://api.argentinadatos.com/v1/feriados/2026](https://api.argentinadatos.com/v1/feriados/2026)
en el navegador:

```json
[
    {"fecha": "2026-01-01", "tipo": "inamovible", "nombre": "Año nuevo"},
    {"fecha": "2026-02-16", "tipo": "inamovible", "nombre": "Carnaval"},
    {"fecha": "2026-02-17", "tipo": "inamovible", "nombre": "Carnaval"},
    ...
]
```

Una lista, con un diccionario por feriado: la **fecha**, el **tipo** (`inamovible`, `trasladable`
o `puente`) y el **nombre**. Vienen ordenados, del primero al último del año. Cambiando el año del
final tenés los de otro año, **2027** incluido.

```python
import requests

anio = 2026
url = f"https://api.argentinadatos.com/v1/feriados/{anio}"
feriados = requests.get(url, timeout=10).json()

print(f"En {anio} hay {len(feriados)} feriados:")
for feriado in feriados:
    print(feriado["fecha"], "-", feriado["nombre"])
```

### ¿Cuándo es el próximo?

Para eso hay que comparar cada fecha con la de hoy. `date.today()` ya lo usaste en
<a href={b + 'clases/bot-siges/'}>el bot</a>. Lo nuevo es **`date.fromisoformat`**, que convierte
el texto `"2026-12-08"` en una **fecha de verdad**, de las que se pueden comparar y restar:

```python
import requests
from datetime import date

feriados = requests.get("https://api.argentinadatos.com/v1/feriados/2026", timeout=10).json()
hoy = date.today()

for feriado in feriados:
    fecha = date.fromisoformat(feriado["fecha"])
    if fecha > hoy:
        faltan = (fecha - hoy).days
        print(f"El próximo feriado es el {feriado['fecha']}: {feriado['nombre']}")
        print(f"Faltan {faltan} días")
        break
```

:::note[📦 Lo nuevo de las fechas]
- **`date.fromisoformat("2026-12-08")`** pasa el texto a fecha. Anda con fechas escritas
  año-mes-día, que es como vienen casi todas las APIs.
- **Restar dos fechas** da la distancia entre las dos, y **`.days`** es esa distancia en días.
- Una fecha sabe sus partes: **`fecha.year`**, **`fecha.month`**, **`fecha.day`**. Y
  **`fecha.weekday()`** dice el día de la semana, con un número: 0 es lunes y 6 es domingo.

Como los feriados vienen ordenados, el primero que está después de hoy **es** el próximo: ahí
el `break` corta el bucle, porque no hace falta seguir mirando.
:::

### La historia del dólar

[https://api.argentinadatos.com/v1/cotizaciones/dolares/blue](https://api.argentinadatos.com/v1/cotizaciones/dolares/blue)
trae **el blue de cada día desde 2011**: una lista de más de 5000 diccionarios, uno por día, del
más viejo al más nuevo.

```json
[
    {"casa": "blue", "compra": 4, "venta": 4, "fecha": "2011-01-03"},
    {"casa": "blue", "compra": 4, "venta": 4, "fecha": "2011-01-04"},
    ...
]
```

Sí: en 2011 el blue estaba a 4 pesos.

Con eso, el último mes:

```python
import requests

url = "https://api.argentinadatos.com/v1/cotizaciones/dolares/blue"
historial = requests.get(url, timeout=20).json()
print(f"Hay {len(historial)} días guardados, desde el {historial[0]['fecha']}")

ultimos = historial[-30:]
ventas = []
for dia in ultimos:
    ventas.append(dia["venta"])

print("Hoy:", ventas[-1])
print("Máximo del mes:", max(ventas))
print("Mínimo del mes:", min(ventas))
print("Promedio del mes:", round(sum(ventas) / len(ventas)))
```

:::note[Algo nuevo: `historial[-30:]`]
Con los dos puntos adentro de los corchetes no pedís **un** elemento sino **un pedazo** de la
lista. `historial[-30:]` es "desde el trigésimo contando del final, hasta el final": los últimos
30. Otros ejemplos: `lista[:3]` son los tres primeros, y `texto[:7]` los primeros 7 caracteres
de un texto.
:::

Cambiando `blue` por `oficial`, `bolsa` (el MEP) o `mayorista` tenés la historia de los otros.

### La inflación, mes por mes

[https://api.argentinadatos.com/v1/finanzas/indices/inflacion](https://api.argentinadatos.com/v1/finanzas/indices/inflacion)
trae la inflación de **cada mes desde 1943**. Cada dato tiene la fecha del último día del mes y el
porcentaje que subieron los precios ese mes:

```json
[
    {"fecha": "1943-03-31", "valor": 1.6},
    ...
    {"fecha": "2026-10-31", "valor": 2.2}
]
```

```python
import requests

url = "https://api.argentinadatos.com/v1/finanzas/indices/inflacion"
inflacion = requests.get(url, timeout=20).json()

print("La inflación de los últimos 12 meses:")
for mes in inflacion[-12:]:
    print(mes["fecha"][:7], "→", mes["valor"], "%")
```

`mes["fecha"][:7]` se queda con `"2026-10"`: el año y el mes, sin el día, que acá no dice nada.

## El dólar de hoy, al momento

ArgentinaDatos guarda **un dato por día**. Para la cotización **del momento**, que se actualiza
varias veces durante el día, hay otra API: **DolarApi**. Es la que vamos a usar en la ventana.

[https://dolarapi.com/v1/dolares/blue](https://dolarapi.com/v1/dolares/blue) devuelve algo así:

```json
{"moneda": "USD", "casa": "blue", "nombre": "Blue", "compra": 1710, "venta": 1730, "fechaActualizacion": "2026-11-25T17:00:00.000Z"}
```

```python
import requests

dolar = requests.get("https://dolarapi.com/v1/dolares/blue", timeout=10).json()
print(f"Dólar {dolar['nombre']}: compra ${dolar['compra']}, venta ${dolar['venta']}")
```

Cambiando el final de la dirección tenés los otros: `oficial`, `bolsa` (el MEP), `tarjeta`. Y
[https://dolarapi.com/v1/dolares](https://dolarapi.com/v1/dolares) los trae **todos juntos**, en
una lista.

:::tip[Dos fuentes, dos números]
Si comparás el blue de hoy de las dos APIs, puede que no coincidan: cada una lo toma de un lugar
distinto y a una hora distinta. Es normal. Cuando uses datos de internet, **decí siempre de dónde
salen**.
:::

## Todo junto: un perro por clic

Ahora se junta con <a href={b + 'mas-alla/tkinter/'}>Tkinter</a>: una ventana con un botón, y
cada vez que lo tocás aparece **la foto** de un perro nuevo. Archivo nuevo, `ventana_perros.py`:

```python
import io
import tkinter as tk
from tkinter import messagebox

import requests
from PIL import Image, ImageTk


def otro_perro():
    try:
        datos = requests.get("https://dog.ceo/api/breeds/image/random", timeout=10).json()
        imagen = requests.get(datos["message"], timeout=10).content
    except requests.exceptions.RequestException:
        messagebox.showerror("Sin conexión", "No me pude conectar. ¿Tenés internet?")
        return

    foto = Image.open(io.BytesIO(imagen))
    foto.thumbnail((400, 400))
    foto_tk = ImageTk.PhotoImage(foto)
    cuadro.config(image=foto_tk)
    cuadro.image = foto_tk


ventana = tk.Tk()
ventana.title("Un perro por clic")

cuadro = tk.Label(ventana, text="Tocá el botón 🐶", font=("Arial", 16))
cuadro.pack(padx=20, pady=20)

tk.Button(ventana, text="Otro perro", font=("Arial", 14), command=otro_perro).pack(pady=10)

ventana.mainloop()
```

Lo nuevo está todo adentro de `otro_perro`:

- **Dos pedidos.** El primero trae el JSON, que dice **dónde** está la foto. El segundo baja **la
  foto misma**. Como una foto no es JSON, en vez de `.json()` se usa **`.content`**: los bytes
  crudos de la imagen.
- **`Image.open(io.BytesIO(imagen))`.** Tkinter solo no sabe abrir fotos JPG, y por eso está
  **Pillow** (`PIL`). `Image.open` espera un archivo, y `io.BytesIO` hace que los bytes que
  bajamos **se comporten como un archivo**, sin guardarlo en el disco.
- **`foto.thumbnail((400, 400))`** la achica para que entre en 400 × 400 sin deformarla. Algunas
  fotos vienen enormes.
- **`ImageTk.PhotoImage`** la convierte a algo que un Label de Tkinter pueda mostrar.

:::danger[La línea que parece que sobra: `cuadro.image = foto_tk`]
Borrala y probá: el cuadro queda **vacío**. La foto es una variable local de la función, y cuando
la función termina, Python la tira porque nadie más la usa. Tkinter no cuenta como alguien que la
usa. Guardándola como atributo del Label, la foto vive mientras viva el Label.
:::

:::note[La ventana se congela un segundo]
Mientras baja la foto, la ventana no responde: el programa está esperando la respuesta y no puede
hacer otra cosa. Con fotos chicas y buen internet casi ni se nota. Arreglarlo del todo se hace con
**hilos**, y eso queda para más adelante.
:::
