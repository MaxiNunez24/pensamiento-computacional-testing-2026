## El problema

Hasta ahora, lo que un programa guardaba se perdía al cerrarlo. Para que el sistema de asistencias
**recuerde**, los datos tienen que quedar en el disco. La pregunta es dónde.

Lo más directo sería un archivo de texto. Pero en el CFP pasa algo que en nuestros ejercicios no
pasaba nunca: **dos personas usando el sistema al mismo tiempo**. Dos preceptoras marcando
asistencia en dos cursos, en el mismo minuto.

Lo medimos, y con archivos pasan dos cosas:

- Con dos personas guardando a la vez, **una de las dos marcas se pierde**. Sin ningún error: el
  sistema dice que guardó y no guardó.
- Si se corta la luz justo mientras se escribe, el archivo **queda ilegible entero**. No la última
  marca: todo.

Una **base de datos** resuelve las dos cosas. Y la que vamos a usar, **SQLite**, tiene una ventaja
enorme: **viene con Python**. No se instala nada.

## Una tabla es una planilla con reglas

Una base de datos guarda **tablas**. Y una tabla se parece mucho a las planillas que usan en el
CFP: columnas con nombre, y una fila por alumno.

| dni | apellido | nombre | activo |
|---|---|---|---|
| 30111222 | Perez | Ana | 1 |
| 28999888 | Gomez | Beto | 1 |

La diferencia es que **la tabla tiene reglas**. Cada columna tiene un tipo, y se puede decir que
una columna **no se repite nunca**: eso se llama **`PRIMARY KEY`**. Para nosotros, el DNI.

Es lo mismo que hacíamos a mano en *"El curso que no deja repetir"*, pero ahora **lo cuida la base**.

Para hablarle a la base se usa un lenguaje propio, **SQL**. Se escribe como un texto adentro de
Python, y `sqlite3` se lo pasa a la base:

```python
import sqlite3

con = sqlite3.connect("asistencias.db")   # abre la base (si no existe, la crea)
con.execute("CREATE TABLE alumnos (dni TEXT PRIMARY KEY, apellido TEXT, nombre TEXT)")
```

`con` es **la conexión**: por ahí pasa todo lo que le pedimos a la base.

## Agregar: el signo de pregunta

Para agregar una fila se usa `INSERT`. Y acá hay una regla que **no se rompe nunca**: los valores
no se pegan en el texto del SQL. Van con **`?`**, y se pasan aparte:

```python
con.execute("INSERT INTO alumnos (dni, apellido, nombre) VALUES (?, ?, ?)",
            ("30111222", "Perez", "Ana"))
```

Un `?` por cada valor, y después los valores **en el mismo orden**, en una tupla.

¿Por qué tanta vuelta, si con un f-string quedaría más corto? Porque el SQL también usa comillas.
Si un apellido tiene una —*D'Alessandro*, *O'Connor*—, esa comilla **cierra el texto adentro del
SQL** y rompe todo. Con `?`, `sqlite3` se encarga de poner cada valor bien, tenga lo que tenga.

## Leer: SELECT

Para leer se usa `SELECT`. Y `ORDER BY` lo devuelve ordenado:

```python
filas = con.execute("SELECT apellido, nombre FROM alumnos ORDER BY apellido").fetchall()
print(filas)    # [('Gomez', 'Beto'), ('Perez', 'Ana')]
```

`.fetchall()` trae **todas** las filas, y cada fila llega como **una tupla**. Es lo mismo que vimos
con tuplas: se lee por posición, `fila[0]`, `fila[1]`.

## Buscar uno: WHERE

`WHERE` filtra: trae solo las filas que cumplen. Y cuando esperás **una sola**, `.fetchone()`:

```python
fila = con.execute("SELECT * FROM alumnos WHERE dni = ?", ("30111222",)).fetchone()
print(fila)     # ('30111222', 'Perez', 'Ana')
```

Si no hay ninguna, `fetchone()` devuelve `None`. Y fijate en la coma de `("30111222",)`: una tupla
de **un solo elemento** se escribe con coma al final. Sin la coma, no es una tupla.

## Otra forma: que la base diga que no

Recién, para no repetir un DNI, **buscaste antes** de insertar. Hay otra forma, con el `try` de
la clase de Excepciones: **intentar el `INSERT`** y que la base te diga que no. Cuando algo rompe una regla de la tabla —como
repetir un `PRIMARY KEY`—, `sqlite3` levanta **`sqlite3.IntegrityError`**.

## Dar de baja no es borrar

En la clase de POO, dar de baja a un alumno era cambiar `activo` a `False`, **nunca borrarlo**:
si se borra, se pierde su asistencia de todo el año y los números del cierre dejan de dar.

En la base es igual. Para cambiar un dato se usa `UPDATE`:

```python
con.execute("UPDATE alumnos SET activo = 0 WHERE dni = ?", ("28999888",))
```

:::caution[El WHERE es lo más importante de esa línea]
Un `UPDATE` sin `WHERE` cambia **todas las filas** de la tabla. Sin avisar, y sin deshacer.
:::

## Contar

La base también sabe hacer cuentas. `COUNT(*)` cuenta las filas, **sin traerlas a Python**:


## De la fila al objeto: el repositorio

Hasta acá, todo devuelve **filas**: tuplas con los datos. Pero el resto del sistema —el bot, la
pantalla de pasar lista— trabaja con **objetos `Alumno`**, que saben armar su nombre completo o
decir si están listos.

Entonces hay que convertir. Y esa conversión va **en un solo lugar**: un archivo que se llama
**`repositorio.py`**, con funciones como `buscar_alumno`, `guardar_alumno` o `dar_de_baja`. Todo lo
que toca la base vive ahí adentro, y **ningún otro archivo del sistema escribe SQL**.

¿Por qué tanto cuidado? Porque así, si mañana cambia la base, **se cambia un solo archivo**. El
resto del programa pide un `Alumno` y recibe un `Alumno`, sin enterarse de dónde salió.

## En tu compu

En VS Code es todo igual, con dos diferencias.

**La base es un archivo.** Con `sqlite3.connect("asistencias.db")` se crea `asistencias.db` en la
carpeta del proyecto, y ahí quedan los datos.

**Hay que confirmar los cambios.** Lo que agregás, cambiás o das de baja queda **pendiente** hasta
que lo confirmás:

```python
con.commit()
```

Sin el `commit()`, cuando el programa termina, los cambios se descartan. Es a propósito: si algo
se corta a mitad de camino, la base vuelve a como estaba en vez de quedar a medio hacer.

:::tip[Para ver adentro de la base]
**[DB Browser for SQLite](https://sqlitebrowser.org/)** es un programa gratis y de código abierto
que abre `asistencias.db` y te muestra las tablas como una planilla. Sirve muchísimo para ver qué
guardó de verdad tu programa.
:::

## Para llevar

- El sistema guarda en una **base de datos** porque con dos personas a la vez, un archivo **pierde
  datos sin avisar**.
- **SQLite viene con Python**: `import sqlite3` y listo.
- Una **tabla** es una planilla con reglas. **`PRIMARY KEY`** = la columna que no se repite.
- Los valores van con **`?`**, nunca pegados en el SQL.
- Para no repetir, se puede **buscar antes** o **intentar** y atajar **`sqlite3.IntegrityError`**.
  Con varias personas cargando a la vez, gana intentar.
- `fetchall()` = todas las filas; `fetchone()` = una, o `None`.
- **Dar de baja es `UPDATE`, no `DELETE`.** Y el `UPDATE` sin `WHERE` cambia todo.
- En tu compu: **`con.commit()`**, o los cambios se pierden.
- Todo lo que toca la base, en **`repositorio.py`**. El resto del programa ve objetos `Alumno`.
