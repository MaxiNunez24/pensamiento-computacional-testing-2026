## El problema

Ya sabés hacer `git add`, `git commit` y `git push` en la terminal. Pero cuando abrís VS Code te
encontrás con esto en la barra de la izquierda:

<PanelGitVSCode
  mensaje=""
  cambios={[{ nombre: 'main.py', letra: 'M' }, { nombre: 'notas.txt', letra: 'U' }]}
  titulo="El panel Source Control (Ctrl+Shift+G)"
/>

Botones, letras de colores, un `+`… y ni un comando a la vista. La buena noticia: **no es otra cosa**.
Cada botón de acá ejecuta exactamente el mismo comando que vos escribís. Si entendés el comando,
entendés el botón.

:::tip[Por qué te conviene saber las dos]
La terminal te enseña **qué pasa**; el editor te lo hace **rápido**. En el laburo vas a usar el
editor casi siempre, pero el día que algo falle, la terminal es la que te dice por qué. Saber las
dos no es el doble de trabajo: es la misma idea vista de dos lados.
:::

## Las letras: el estado de cada archivo

Al lado de cada archivo aparece una letra. **Es el estado de Git, no una decoración**:

| Letra | Color | Qué significa | En la terminal lo verías como |
|---|---|---|---|
| **U** | verde | *Untracked*: archivo nuevo, Git todavía no lo sigue | `Untracked files` |
| **M** | ámbar | *Modified*: ya estaba, y lo cambiaste | `Changes not staged for commit` |
| **A** | verde | *Added*: preparado para el próximo commit | `Changes to be committed` |
| **D** | rojo | *Deleted*: lo borraste | `deleted:` |

## `git add` → el `+`

Para preparar un archivo, en la terminal escribís `git add main.py`. En el editor, pasás el mouse por
encima del archivo y tocás el **`+`**:

## `git commit` → la caja y el botón azul

Escribís el mensaje en la caja de arriba y tocás **✓ Commit**. Es el equivalente exacto de
`git commit -m "tu mensaje"`.

<PanelGitVSCode
  mensaje="Agregar el cartón del bingo"
  staged={[{ nombre: 'main.py', letra: 'M' }]}
  cambios={[{ nombre: 'notas.txt', letra: 'U' }]}
  resaltar="commit"
  titulo="Mensaje escrito y listo para confirmar"
/>

:::caution[Ojo con lo que entra al commit]
En el panel de arriba, `notas.txt` está en **CHANGES**, no en **STAGED CHANGES**. Si tocás Commit
ahora, ese archivo **no entra**. Es el mismo error clásico de la terminal: hacer `commit` sin haber
hecho `add`.
:::

## `git push` y `git pull` → el botón de sincronizar

Arriba a la derecha del panel hay un ícono de flechas en círculo. Ese botón hace **las dos cosas**:
primero trae lo que haya en GitHub (`pull`) y después manda lo tuyo (`push`).

<PanelGitVSCode
  staged={[]}
  cambios={[{ nombre: 'main.py', letra: 'M' }]}
  resaltar="sync"
  titulo="Sync Changes: pull y push de una"
/>

:::note[Es el mismo botón que ya usaste hoy]
El botón **🔄 Sincronizar** de esta plataforma está hecho a propósito con esa idea: `push` sube lo
tuyo, `pull` trae lo guardado. Cuando lo veas en VS Code no vas a estar aprendiendo algo nuevo.
:::

## La tabla que te conviene tener a mano

| En la terminal | En VS Code |
|---|---|
| `git status` | El panel mismo: los archivos y sus letras |
| `git add archivo` | El **`+`** al lado del archivo |
| `git add .` | El **`+`** al lado del título **CHANGES** |
| `git restore --staged archivo` | El **`−`** al lado del archivo preparado |
| `git commit -m "mensaje"` | Escribir en la caja y tocar **✓ Commit** |
| `git push` / `git pull` | **Sync Changes** (el ícono de flechas) |
| `git log` | La vista **Graph** / el historial del panel |

## Para llevar

- El editor **no reemplaza** a Git: le pone botones adelante.
- Las letras (**U**, **M**, **A**, **D**) son los estados de Git, los mismos de `git status`.
- El orden nunca cambia: **preparar → confirmar → sincronizar** (`add` → `commit` → `push`).
- Si algo falla y el botón no te dice por qué, abrí la terminal: ahí está el mensaje completo.
