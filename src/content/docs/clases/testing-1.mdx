Todos ustedes ya probaron sus programas. Los corrieron, escribieron algo, miraron
la pantalla y dijeron "anda". **Eso es probar.** Lo que cambia acá es quién lo hace: en vez
de vos cada vez, lo hace el programa, siempre igual y sin cansarse.

:::note[¿Por qué esto tiene una clase entera?]
Porque el curso se llama **Pensamiento Computacional y Testing de Aplicaciones**. Y porque el
día que el sistema de asistencias tenga 40 pantallas, probarlo a mano después de cada cambio
va a ser imposible.
:::

## Lo que ya venís haciendo sin saberlo

Cada vez que tocás **Verificar** en un ejercicio, se corre un test. El botón no mira si tu
código "está lindo": corre tu función con valores concretos y compara el resultado con el
esperado. Eso es todo lo que es un test.

```python
assert sumar(2, 3) == 5
```

`assert` significa "afirmo que esto es verdad". Si lo es, no pasa nada. Si no lo es, el
programa se detiene y avisa. **Un test es una afirmación sobre tu código.**

:::tip[La regla práctica]
Muchas unitarias (son baratas y rápidas), algunas de integración, **pocas** de punta a punta:
son las más lentas y las que más se rompen por cualquier cosa.
:::

## Ahora escribís vos

Acá está la parte que importa. Un test **no** se juzga por lo que dice, sino por lo que
**detecta**: tiene que pasar con el código que anda y fallar con el código roto. Si no
distingue uno del otro, no sirve, por más lindo que se vea.

<EscribirTest
  titulo="El test que atrapa el bug"
  dificultad="🟠"
  correcta={`def promedio(notas):
    if not notas:
        return 0
    return sum(notas) / len(notas)`}
  rotas={[
    { pista: 'la versión que se rompe con la lista vacía (divide por cero)',
      codigo: `def promedio(notas):
    return sum(notas) / len(notas)` },
    { pista: 'la versión que se olvida del último elemento',
      codigo: `def promedio(notas):
    if not notas:
        return 0
    return sum(notas[:-1]) / len(notas[:-1]) if len(notas) > 1 else notas[0]` },
    { pista: 'la versión que devuelve la suma en vez del promedio',
      codigo: `def promedio(notas):
    if not notas:
        return 0
    return sum(notas)` },
  ]}
  starter={`# La función promedio(notas) ya está escrita: vos NO la tocás.
# Escribí los assert que la pongan a prueba de verdad.

assert promedio([10, 10]) == 10
`}
  pistas={[
    'Con un solo caso no alcanza: <code>promedio([10, 10])</code> da 10 tanto en la versión buena como en la que suma sin dividir… ¿o no? Probalo.',
    'Pensá en los <strong>bordes</strong>: ¿qué pasa con la lista vacía? ¿Y con un solo elemento?',
    'Un promedio no siempre da un número redondo. Probá con <code>[7, 8]</code>.',
  ]}
>
  Escribí los `assert` necesarios para que **pasen con la versión correcta** y **fallen con
  las tres versiones rotas**. Abajo vas a ver cuáles atrapaste y cuál se te escapó.
</EscribirTest>

:::caution[Lo que acabás de descubrir]
Un test que pasa **no** significa que el código esté bien: significa que ese caso anda.
Por eso los bugs se escapan — no porque nadie pruebe, sino porque nadie probó *ese* caso.
:::
