## Dos molestias que vamos a resolver

1. **Los objetos se imprimen feo:** `print(ana)` muestra `<__main__.Alumno object at 0x...>` 😵.
2. **Cualquiera rompe los datos:** `cuenta.saldo = -9999` saltea toda tu lógica de `extraer()` 😱.

## `__str__`: que el objeto se imprima lindo

`__str__` es un **método especial** (*dunder*): Python lo llama solo cuando hacés `print(obj)` o
`str(obj)`. Vos definís qué texto devuelve.

```python
class Alumno:
    def __init__(self, nombre, nota):
        self.nombre = nombre
        self.nota = nota
    def __str__(self):
        return f"Alumno: {self.nombre} (nota {self.nota})"

print(Alumno("Ana", 9))   # Alumno: Ana (nota 9)
```

## Encapsulamiento: proteger los datos

**Encapsular** es esconder los datos internos y obligar a tocarlos **solo por métodos controlados**
(como un cajero: usás los botones, no metés la mano en la caja fuerte). En Python, un atributo que
arranca con **`_`** señala *"esto es interno, no lo toques de afuera"*.

```python
class CuentaBancaria:
    def __init__(self, saldo=0):
        self._saldo = saldo            # interno
    def depositar(self, monto):
        if monto > 0:
            self._saldo += monto
    def ver_saldo(self):
        return self._saldo
```

En un diagrama, `-` es privado y `+` es público:

## Para llevar

- `__str__` define cómo se imprime tu objeto (hay más *dunder*: `__repr__`, `__len__`, `__eq__`…).
- Encapsular = datos internos con `_` + métodos que controlan el acceso (la "puerta").
- En el diagrama: `-` privado, `+` público.
