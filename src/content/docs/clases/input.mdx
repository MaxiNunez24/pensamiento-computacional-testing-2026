## El problema

Hasta ahora tus programas hacían siempre lo mismo, porque los datos estaban escritos en el código:

```python
nombre = "Ana"
print(f"¡Hola, {nombre}!")
```

Siempre saluda a Ana. Para que salude a quien lo use, hay que **preguntárselo**.

```python
nombre = input("¿Cómo te llamás? ")
print(f"¡Hola, {nombre}!")
```

`input()` frena el programa, muestra el mensaje, espera a que la persona escriba y apriete Enter, y
**devuelve lo que escribió**.

:::note[Cómo funciona acá adentro]
En tu compu, `input()` espera a que teclees. En esta página no hay teclado para el programa, así que
las respuestas se cargan de antemano en la caja **⌨️ Entradas** que vas a ver abajo del editor: el
programa las va tomando en orden, una por cada `input()`.

Lo que ves en la salida es idéntico a una terminal de verdad. Y podés **editar esas entradas** para
probar otros casos, que es justamente lo que hacés cuando ejecutás un programa varias veces.
:::

## El prompt

El texto que le pasás a `input()` es el **prompt**: lo que la persona lee antes de escribir.

```python
edad = input("¿Cuántos años tenés? ")
```

:::tip[Dejá un espacio al final]
`input("¿Cuántos años tenés? ")` con el espacio se ve así:

```
¿Cuántos años tenés? 20
```

Y sin el espacio, así:

```
¿Cuántos años tenés?20
```

Es un detalle mínimo que hace que el programa se sienta prolijo.
:::

## Todo lo que entra, entra como texto

Esta es **la** trampa de `input()`, y te va a morder al menos una vez:

```python
edad = input("¿Cuántos años tenés? ")   # escribe 20
print(edad + 1)                          # 💥 TypeError
```

Aunque la persona escriba `20`, `input()` devuelve **el texto** `"20"`, no el número `20`. Y ya viste
que texto y número no se mezclan.

Peor todavía, a veces **no falla** y hace algo raro:

```python
edad = input("Edad: ")     # escribe 20
print(edad * 3)            # 202020   ← repitió el texto tres veces
```

No dio error, pero tampoco hizo lo que querías. De esos bugs son los que cuestan encontrar.

La solución es **convertir**:

```python
edad = int(input("¿Cuántos años tenés? "))     # texto → entero
precio = float(input("Precio: "))              # texto → decimal
```

:::caution[¿Dónde va el `int()`?]
```python
edad = int(input("Edad: "))     # ✅ convierte lo que devolvió input
edad = int(input)               # ❌ eso intenta convertir la función misma
```
Se lee de adentro hacia afuera: primero corre `input(...)`, y lo que devuelve se lo pasás a `int()`.
:::

## Varios datos

Un `input()` por cada dato que necesites:

```python
nombre = input("Nombre: ")
edad = int(input("Edad: "))
print(f"{nombre} tiene {edad} años")
```

Se ejecutan **en orden**, así que las respuestas se consumen en ese mismo orden.

## Cuándo NO usar `input()`

Un detalle que vale para el resto del curso: `input()` sirve para programas que conversan con una
persona. Pero cuando quieras **reutilizar** un pedazo de lógica, conviene que los datos entren **por
parámetro**, no preguntando.

```python
# Difícil de reutilizar y de probar: siempre pregunta
edad = int(input("Edad: "))

# Fácil de reutilizar: le pasás la edad de donde sea
def es_mayor(edad):
    return edad >= 18
```

Cuando lleguemos a **funciones** vas a ver por qué: un pedazo de código que pregunta por su cuenta no
se puede usar desde otro lado ni verificar automáticamente.
