## El problema

Todo lo que hiciste hasta ahora vive en la **memoria RAM**: existe mientras el programa corre y
desaparece cuando se cierra.

```python
alumnos = ["Guada", "Brandon", "Yoda"]
print(alumnos)
```

Cerrás el programa, lo volvés a abrir... y la lista no está más. Si tuvieras que cargar cien alumnos
a mano cada vez que arrancás, el programa sería inútil.

Para que los datos **sobrevivan**, hay que sacarlos de la RAM y ponerlos en el **disco**: un archivo.

:::note[La jerarquía en una frase]
La **RAM** es rápida pero se borra al apagar. El **disco** es más lento pero recuerda. Cuando querés
que algo dure entre ejecuciones, va al disco.
:::

## Abrir un archivo

```python
archivo = open("datos.txt", "w")
archivo.write("Hola")
archivo.close()
```

`open()` recibe **dónde** está el archivo y **para qué** lo abrís (el *modo*):

| Modo | Qué hace | Si el archivo no existe |
|---|---|---|
| `"r"` | Leer (es el que se usa por defecto) | 💥 Error |
| `"w"` | Escribir **borrando todo** lo anterior | Lo crea |
| `"a"` | Escribir **agregando al final** | Lo crea |
| `"x"` | Crear, y fallar si ya existe | Lo crea |

:::caution[`"w"` borra sin preguntar]
Abrir con `"w"` un archivo que ya tiene contenido lo **vacía en el acto**, antes incluso de que
escribas nada. Si querés sumar sin perder lo que había, el modo es `"a"`.
:::

## Siempre `with`

Ese `archivo.close()` del ejemplo es un problema esperando: si el programa falla entre el `open` y el
`close`, el archivo queda abierto y podés perder lo que escribiste.

Por eso en Python **siempre** se usa `with`:

```python
with open("datos.txt", "w", encoding="utf-8") as archivo:
    archivo.write("Hola")
# acá afuera ya está cerrado, incluso si algo falló adentro
```

El `with` se encarga de cerrarlo pase lo que pase. No es una preferencia de estilo: es la forma
correcta.

:::tip[¿Por qué `encoding="utf-8"`?]
Porque nuestros textos tienen tildes y ñ. Sin especificar el encoding, Python usa el del sistema
operativo, que cambia entre Windows y Linux — y el mismo programa que anda en tu casa te muestra
`Ã±` en la máquina del CFP. Ponelo siempre.
:::

## Leer

Tres formas, según lo que necesites:

```python
with open("datos.txt", "r", encoding="utf-8") as archivo:
    todo = archivo.read()          # un solo string con TODO

with open("datos.txt", "r", encoding="utf-8") as archivo:
    lineas = archivo.readlines()   # una lista, un elemento por línea

with open("datos.txt", "r", encoding="utf-8") as archivo:
    for linea in archivo:          # de a una, sin cargar todo en memoria
        print(linea, end="")
```

La tercera es la mejor para archivos grandes: no necesita meter el archivo entero en la RAM.

:::note[El `end=""` del `print`]
Cada línea que leés **ya trae su salto de línea** al final. Si además `print` agrega el suyo, te
quedan renglones vacíos en el medio. Por eso el `end=""`.
:::

## Escribir: `write` y `print`

```python
archivo.write("Hola\n")           # NO agrega salto de línea: se lo ponés vos
print("Hola", file=archivo)       # sí lo agrega, como cualquier print
```

Las dos sirven. `print(..., file=archivo)` suele ser más cómoda justamente porque se encarga del
salto de línea.

## Rutas: dónde busca Python

Cuando escribís `open("datos.txt")`, Python lo busca **desde la carpeta donde estás parado**, no
desde donde está el archivo `.py`. Es la causa número uno del `FileNotFoundError`.

```python
open("datos.txt")                    # ruta relativa: al lado de donde ejecutás
open("clase_archivos/datos.txt")     # relativa, bajando una carpeta
open("/home/maxi/datos.txt")         # absoluta: siempre el mismo lugar
```

:::tip[Si te tira `FileNotFoundError`]
No es que el archivo no exista: es que **no está donde Python está mirando**. Antes de pelearte con
la ruta, preguntale dónde está parado:

```python
from pathlib import Path
print(Path.cwd())      # la carpeta actual
```
:::

## Trabajar con carpetas: `pathlib`

```python
from pathlib import Path

carpeta = Path("practica_archivos")

for archivo in carpeta.iterdir():    # recorre lo que hay adentro
    print(archivo.name)

Path("datos.txt").exists()           # ¿existe?
```

`Path` arma las rutas correctamente en Windows, Linux y macOS sin que tengas que pensar en las barras.

:::note[Los archivos de esta página son de mentira]
Python corre acá adentro del navegador, con un sistema de archivos **virtual**: los archivos que
creás existen de verdad para el programa, pero viven en la pestaña y desaparecen al recargar. No
toca nada de tu compu. En VS Code, el mismo código escribe archivos posta.
:::
