## Scope: dónde vive cada variable

Probá adivinar qué imprime esto:

```python
def saludar():
    mensaje = "Hola"

saludar()
print(mensaje)      # 💥 NameError: name 'mensaje' is not defined
```

`mensaje` **nació y murió adentro de la función**. Cuando la función termina, sus variables
desaparecen. A eso se le dice **scope local**.

Al revés sí funciona: desde adentro podés **leer** lo de afuera.

```python
titulo = "Curso 2026"           # variable global

def mostrar():
    print(titulo)               # ✅ puede leerla

mostrar()
```

Pero **asignarle** algo no la modifica: crea una nueva, local, que tapa a la de afuera.

```python
contador = 0

def sumar():
    contador = contador + 1     # 💥 UnboundLocalError

sumar()
```

:::caution[Por qué ese error es tan raro]
Python ve que en algún lugar de la función le asignás a `contador`, así que decide que es **local**.
Y cuando llega a leer `contador + 1`, esa variable local todavía no tiene valor. De ahí el
"UnboundLocalError": no es que no exista la global, es que decidió no mirarla.
:::

### La solución no es `global`

Existe la palabra `global`, pero **casi nunca es la respuesta**. Una función que modifica variables
de afuera es difícil de entender y de probar: para saber qué hace tenés que leer todo el programa.

La forma sana es **recibir y devolver**:

```python
def sumar(contador):
    return contador + 1

contador = 0
contador = sumar(contador)      # queda claro qué entra y qué sale
```

Esta es la idea de fondo de todo el curso: una función que solo depende de sus parámetros y solo
comunica su resultado con `return` se puede leer, probar y reusar sola.

## Valores por defecto

Un parámetro puede tener un valor que se usa si quien llama no lo pasa:

```python
def saludar(nombre, saludo="Hola"):
    return f"{saludo}, {nombre}!"

saludar("Ana")                  # "Hola, Ana!"
saludar("Ana", "Buenas")        # "Buenas, Ana!"
```

Los que tienen valor por defecto van **siempre al final**, después de los obligatorios. Si no, Python
no sabría a cuál corresponde cada valor.

:::caution[La trampa clásica: nunca uses una lista como valor por defecto]
```python
def agregar(item, lista=[]):        # ⚠️ mal
    lista.append(item)
    return lista

agregar("a")    # ['a']
agregar("b")    # ['a', 'b']  ← ¿¿y la 'a'??
```

El valor por defecto **se crea una sola vez**, cuando se define la función — no en cada llamada. Así
que todas las llamadas comparten la misma lista. La forma correcta:

```python
def agregar(item, lista=None):
    if lista is None:
        lista = []
    lista.append(item)
    return lista
```
:::

## Argumentos por nombre

Al llamar, podés nombrar los parámetros y el orden deja de importar:

```python
def crear_alumno(nombre, edad, activo=True):
    ...

crear_alumno("Guada", 25)
crear_alumno(edad=25, nombre="Guada")        # el orden no importa
crear_alumno("Guada", 25, activo=False)
```

:::tip[Cuándo conviene nombrarlos]
Cuando el valor solo no se explica:

```python
configurar(True, False, True)                       # ...¿qué es cada uno?
configurar(debug=True, cache=False, logs=True)      # ah, listo
```
:::

## `*args`: una cantidad indefinida de valores

¿Y si no sabés cuántos argumentos te van a pasar?

```python
def sumar(*numeros):
    total = 0
    for n in numeros:
        total += n
    return total

sumar(1, 2)           # 3
sumar(1, 2, 3, 4, 5)  # 15
sumar()               # 0
```

El `*` junta todo lo que venga en una **tupla**. El nombre `args` es solo una convención: lo que
importa es el asterisco.

## `**kwargs`: lo mismo, pero con nombre

```python
def describir(**datos):
    for clave, valor in datos.items():
        print(f"{clave}: {valor}")

describir(nombre="Guada", edad=25)
# nombre: Guada
# edad: 25
```

El `**` junta los argumentos con nombre en un **diccionario**.

Todo junto, el orden es siempre este:

```python
def funcion(obligatorio, con_defecto="x", *args, **kwargs):
    ...
```

:::note[Dónde ya los viste sin saberlo]
`print("a", "b", "c", sep=" - ", end="")` es exactamente esto: `"a", "b", "c"` entran por `*args` y
`sep` / `end` por `**kwargs`. Por eso `print` acepta cualquier cantidad de cosas.
:::

## Desempaquetar al llamar

El mismo `*` sirve al revés: para **abrir** una colección y pasar sus elementos como argumentos
sueltos.

```python
numeros = [1, 2, 3]

sumar(numeros)      # ❌ le pasás UNA lista
sumar(*numeros)     # ✅ le pasás 1, 2 y 3
```

Y con diccionarios:

```python
datos = {"nombre": "Guada", "edad": 25}
crear_alumno(**datos)      # equivale a crear_alumno(nombre="Guada", edad=25)
```

Regla para acordarse: **en la definición, el `*` junta; en la llamada, el `*` reparte.**

## 🏗️ El sistema: pasar lista sin escribir de más

Todo lo de esta clase —valores por defecto, `*args`, `**kwargs`— existe para lo mismo: que quien
usa la función escriba **solo lo que no es obvio**. En una lista de asistencia eso se nota mucho,
porque el día normal es "vinieron casi todos".

<EjercicioPython
  titulo="Lo normal es que hayan venido"

  pistas={[
    "El valor por defecto se escribe en la firma de la función, al lado del parámetro.",
    "Fijate que el primer test llama a <code>marcar</code> con dos argumentos y el segundo con tres. La misma función tiene que aceptar las dos formas.",
  ]}
>
Completá `marcar(dia, dni, estado)` para que **el estado sea opcional**: si no se lo pasan, vale
`"P"`.

:::note[Por qué esto no es un capricho]
La preceptora abre el sistema y marca a los cinco que faltaron. Los otros veinticinco vinieron, y
escribir `"P"` veinticinco veces es la clase de trabajo que hace que la gente vuelva al papel.

Un valor por defecto bien elegido **es una decisión sobre cómo se usa el sistema**, no un detalle
de sintaxis.
:::
</EjercicioPython>

:::note[Por qué `estado` va después del `*dnis`]
Porque queda **obligatoriamente por nombre**. Si estuviera antes, un
`marcar_varios(dia, "A", "30111222")` se leería como "marcá a los alumnos A y 30111222", y nadie se
enteraría hasta ver la planilla. Poniéndolo después del `*`, la única forma de pasarlo es
`estado="A"` — y ahí no hay confusión posible.
:::
