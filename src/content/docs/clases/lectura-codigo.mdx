Programar es, en buena medida, **leer** código que no escribiste vos — a veces de otra persona, a
veces tuyo de hace dos semanas, que es casi lo mismo.

Acá los ejercicios funcionan distinto: **primero señalás la línea** donde creés que está el
problema, y recién si acertás se habilita el arreglo. Es a propósito. Si te dejáramos editar desde el
principio, la tentación es tocar cosas hasta que funcione — y así no se aprende a leer.

:::caution[Uno de los diez no tiene ningún error]
No sabés cuál. Así que no alcanza con encontrar *algo raro*: tenés que entender qué hace el programa
antes de decidir. Ese es todo el ejercicio.
:::

## Cómo leer código ajeno

Antes de buscar el error, tres preguntas:

1. **¿Qué debería hacer?** Leé el enunciado, no el código.
2. **¿Qué hace en realidad?** Seguilo línea por línea, anotando cuánto vale cada variable.
3. **¿Dónde se separan esas dos historias?** Ahí está el bug.

| Tipo de error | Cómo se manifiesta |
|---|---|
| **Sintaxis** | No arranca. Python te marca la línea. |
| **Ejecución** | Arranca y explota a mitad de camino (`TypeError`, `KeyError`, `IndexError`). |
| **Lógica** | Anda perfecto… y da mal el resultado. **El más peligroso**, porque no avisa. |

<EncontrarElError
  titulo="4 · La suma que se reinicia"
  dificultad="🌿"
  codigo={`numeros = [5, 15, 3, 20, 8, 12]\nsuma = 0\nfor n in numeros:\n    if n > 10:\n        suma = 0\n        suma += n\nprint(f"Suma de mayores a 10: {suma}")`}
  errores={[5]}
  explicacion="Esa línea pone el acumulador en cero cada vez que encuentra un número grande, así que al final solo queda el último. Arriba ya se inicializa en 0: esta directamente sobra."
  tests={`assert salida.strip() == "Suma de mayores a 10: 47", f"imprimió {salida.strip()!r}"`}
  arreglo="completo"
  pistas={[
    "Seguí el valor de <code>suma</code> vuelta por vuelta: 15… 20… 12. ¿Se van sumando o se pisan?",
    "Hay una línea que se ejecuta muchas veces cuando debería ejecutarse una sola. ¿Cuál?",
  ]}
>
Debería dar `47` (15 + 20 + 12) pero imprime `12`.

:::note[Acá el arreglo no es cambiar esa línea]
Una vez que la ubiques se abre el código completo, porque este bug se resuelve **moviendo** cosas,
no reescribiendo un renglón.
:::
</EncontrarElError>
