## El problema

Guardemos las coordenadas de un punto en una lista:

```python
punto = [3, 5]
punto[0] = 99      # ...y ahora el punto está en otro lado
```

Nada te impide cambiarlo. Para una lista de compras eso está perfecto — querés agregar y sacar cosas.
Pero hay datos que **no deberían poder cambiar**: las coordenadas de un punto, una fecha, los colores
de una bandera, el nombre y el DNI de una persona.

Una **tupla** es una colección que, una vez creada, **no se puede modificar**.

```python
punto = (3, 5)
punto[0] = 99      # 💥 TypeError: 'tuple' object does not support item assignment
```

:::note[Que no se pueda cambiar es la ventaja]
Suena a limitación, pero es una garantía: si recibís una tupla, sabés que **nadie te la va a cambiar
por debajo**. Es el mismo espíritu que poner un dato en mayúsculas para decir "esto es una constante",
solo que acá Python lo hace cumplir de verdad.
:::

## Cómo se arma

```python
punto = (3, 5)
colores = ("rojo", "verde", "azul")
vacia = ()
un_solo = (42,)        # ← ojo con esa coma
```

Los paréntesis son opcionales; **lo que hace la tupla es la coma**:

```python
punto = 3, 5           # también es una tupla
```

:::caution[La tupla de un solo elemento]
```python
esto_no = (42)         # esto es el número 42, los paréntesis solo agrupan
esto_si = (42,)        # ESTO es una tupla de un elemento
```
Sin la coma no hay tupla. Es de esos detalles que te hacen perder veinte minutos la primera vez.
:::

Leer y recorrer funciona igual que en una lista:

```python
punto[0]                   # 3
len(colores)               # 3
"rojo" in colores          # True
for c in colores:
    print(c)
```

Lo único que no podés es **modificarla**: nada de `append`, `remove`, ni asignar por posición.

## Desempaquetado: la parte que más se usa

Podés repartir una tupla en varias variables de una sola vez:

```python
punto = (3, 5)
x, y = punto           # x vale 3, y vale 5
```

Tiene que haber **tantas variables como elementos**, o Python se queja.

Esto explica un truco que quizás ya viste:

```python
a = 1
b = 2
a, b = b, a            # intercambia los valores, sin variable auxiliar
```

Del lado derecho se arma la tupla `(2, 1)` y del izquierdo se desempaqueta. Por eso funciona.

Y también explica el `for` sobre `.items()` de los diccionarios:

```python
for clave, valor in precios.items():
    ...
```

`.items()` va entregando tuplas de dos, y el `for` las desempaqueta en cada vuelta.

## Devolver más de un valor

Esta es **la** razón por la que vas a usar tuplas todo el tiempo. Una función devuelve una sola cosa…
pero si esa cosa es una tupla, en la práctica devuelve varias:

```python
def dividir(a, b):
    return a // b, a % b       # devuelve una tupla

cociente, resto = dividir(10, 3)     # y se desempaqueta al recibirla
print(cociente, resto)               # 3 1
```

## `zip`: recorrer dos listas a la vez

```python
nombres = ["Guada", "Brandon", "Yoda"]
notas = [10, 8, 9]

for nombre, nota in zip(nombres, notas):
    print(f"{nombre} sacó {nota}")
```

`zip` va emparejando: primero con primero, segundo con segundo. Devuelve tuplas, que el `for`
desempaqueta.

:::caution[`zip` corta con la más corta]
Si una lista tiene 3 elementos y la otra 5, `zip` te da 3 pares y **descarta los que sobran, sin
avisar**. Cuando las listas tendrían que ir apareadas, conviene chequear que midan lo mismo.
:::

## ¿Lista o tupla?

| Usá **lista** cuando... | Usá **tupla** cuando... |
|---|---|
| la cantidad de elementos puede cambiar | son un conjunto fijo de datos |
| todos los elementos son lo mismo | cada posición significa algo distinto |
| necesitás agregar, sacar u ordenar | querés garantizar que nadie lo modifique |
| *notas de un alumno, productos del carrito* | *coordenadas, una fecha, un registro* |

:::tip[Un bonus concreto]
Las tuplas **pueden ser claves de un diccionario** y las listas no, justamente porque no cambian:

```python
distancias = {("Buenos Aires", "Córdoba"): 700}
```
:::
