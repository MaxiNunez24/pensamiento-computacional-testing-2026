## El problema

Con archivos de texto ya sabés guardar cosas. Probemos con un diccionario:

```python
alumno = {"nombre": "Guada", "edad": 25}

with open("alumno.txt", "w", encoding="utf-8") as f:
    f.write(str(alumno))
```

El archivo queda con `{'nombre': 'Guada', 'edad': 25}`. Parece que funcionó... hasta que lo querés
leer de vuelta:

```python
with open("alumno.txt", encoding="utf-8") as f:
    recuperado = f.read()

recuperado["nombre"]   # 💥 TypeError
```

Lo que recuperaste es **un texto que se parece a un diccionario**, no un diccionario. Perdiste la
estructura: los números son texto, no podés acceder por clave, nada.

**JSON** resuelve exactamente eso: guardar estructuras enteras y recuperarlas tal como estaban.

## Qué es JSON

Un formato de texto para representar datos, que **todos los lenguajes entienden**. Un programa en
Python guarda un JSON y otro en JavaScript lo lee sin problema. Por eso es la forma en que viaja
casi toda la información por internet.

```json
{
  "nombre": "Guada",
  "edad": 25,
  "notas": [10, 8, 9],
  "activo": true
}
```

Se parece muchísimo a un diccionario de Python, y no es casualidad.

| Python | JSON |
|---|---|
| `dict` | objeto `{}` |
| `list` | arreglo `[]` |
| `str` | string (**siempre comillas dobles**) |
| `int` / `float` | number |
| `True` / `False` | `true` / `false` |
| `None` | `null` |

:::caution[Las diferencias que te van a morder]
- En JSON las comillas son **siempre dobles**: `"nombre"`, nunca `'nombre'`.
- Se escribe `true` / `false` / `null` en minúscula, no `True` / `False` / `None`.
- **No se permite coma al final** del último elemento.

Por eso no alcanza con copiar un diccionario de Python y decir que es JSON: hay que convertirlo.
:::

## Las cuatro funciones

El módulo `json` tiene cuatro, y la diferencia está en si trabajan con **archivos** o con **textos**:

| | De Python a JSON | De JSON a Python |
|---|---|---|
| **con un archivo** | `json.dump(datos, archivo)` | `json.load(archivo)` |
| **con un string** | `json.dumps(datos)` | `json.loads(texto)` |

La `s` final significa *string*. Las que más vas a usar son `dump` y `load`, las de archivo.

```python
import json

datos = {"nombre": "Guada", "notas": [10, 8]}

# Guardar
with open("datos.json", "w", encoding="utf-8") as f:
    json.dump(datos, f, ensure_ascii=False, indent=2)

# Leer
with open("datos.json", encoding="utf-8") as f:
    recuperado = json.load(f)

recuperado["notas"][0]   # 10  ← ahora sí, es un diccionario de verdad
```

:::tip[Los dos parámetros que conviene poner siempre]
- **`ensure_ascii=False`** → si no, las tildes y la ñ se guardan como `\u00f1` y el archivo queda
  ilegible para un humano. Los datos están bien igual, pero no podés abrirlo y entenderlo.
- **`indent=2`** → guarda el JSON con saltos de línea y sangría, en vez de todo apretado en un
  renglón. Sin esto, un archivo de 50 alumnos es una sola línea infinita.
:::

## Un caso real: la agenda

Con esto ya podés hacer un programa que recuerde cosas entre ejecuciones:

```python
import json
from pathlib import Path

def cargar_agenda(ruta):
    if not Path(ruta).exists():      # la primera vez todavía no hay archivo
        return {}
    with open(ruta, encoding="utf-8") as f:
        return json.load(f)
```

Ese `if` de la primera vez es importante: si el archivo no existe, `open` en modo lectura revienta.
Devolver una estructura vacía es lo que hace que el programa arranque bien la primera vez.

## Cuándo JSON y cuándo texto plano

| | |
|---|---|
| **Texto plano** (`.txt`) | Un log, una lista simple de líneas, algo que va a leer una persona |
| **JSON** (`.json`) | Estructuras: diccionarios, listas anidadas, datos que otro programa va a volver a cargar |

Regla práctica: si lo que guardás **no es una lista de líneas sueltas**, es JSON.
