class Curso:
    def __init__(self, nombre):
        self.nombre = nombre
        self._alumnos = {}

    def agregar(self, alumno):
        if alumno.dni in self._alumnos:
            raise ValueError(f"ya hay un alumno con el DNI {alumno.dni}")
        self._alumnos[alumno.dni] = alumno

    def buscar(self, dni):
        return self._alumnos.get(dni)

    def alumnos(self):
        return list(self._alumnos.values())

## El problema

El `Alumno` ya existe: lo armamos en POO, le pusimos control de DNI en Excepciones. Pero vive
**adentro de un programa que corre en una sola compu**, y lo ve solo quien lo corre.

La preceptora no va a abrir VS Code. Quiere **abrir el navegador, entrar a una dirección y ver la
lista del curso**. Hoy vamos a llegar a eso, en tres pasos:

1. **Repasar** el `Alumno` y armar el `Curso`, con todo lo que vimos de POO y Excepciones.
2. Hacer que esos objetos **se conviertan en HTML**, como hiciste con el catálogo.
3. Que **Flask** le mande ese HTML al navegador cuando alguien lo pida.

Al final de la clase, en tu compu, esto va a andar:

```text
http://127.0.0.1:5000/alumnos
```

```text
1° A
  • Perez, Ana — 50.0%
  • Gomez, Beto — 0.0%
```

## Parte 1 · El Alumno y el Curso

Un repaso rápido de lo que ya sabés, antes de usarlo:

| Lo que vimos | Para qué sirve en el sistema |
|---|---|
| `class` y `__init__` | El molde del Alumno y los datos con que nace |
| `self` | "Este alumno": el objeto que está ejecutando el método |
| `_marcas` (con guion bajo) | Un dato que no se toca de afuera: se cambia solo con `marcar()` |
| `__str__` | Cómo se ve el alumno cuando lo imprimís |
| `raise ValueError(...)` | Frenar todo cuando un dato no sirve |
| `try` / `except` | Atajar ese error y seguir |


## Parte 3 · Flask: la página se arma cuando alguien la pide

Ya tenés una función que **devuelve la página**. Lo que falta es alguien que, cuando el navegador
pide `/alumnos`, **llame a esa función y le mande lo que devuelve**. Eso es **Flask**.

<Mermaid code={`sequenceDiagram
    participant N as Navegador
    participant F as Flask (app.py)
    participant M as Tus funciones
    N->>F: Pido /alumnos
    F->>M: pagina(curso)
    M-->>F: El HTML, como texto
    F-->>N: Te mando la página

La diferencia con el catálogo es **cuándo** se arma el HTML. El catálogo lo armabas una vez y
quedaba guardado en un archivo. Con Flask, se arma **cada vez que alguien entra**. Por eso, si Ana
tiene una marca nueva, el que recarga la página la ve.

:::caution[Esta parte necesita internet]
Flask no viene con Python: hay que instalarlo con `pip`, como Playwright en la clase del bot. Si en
el CFP no hay internet, seguí con el proyector y hacelo en casa: es copiar dos archivos.
:::

### 🧩 Desafíos, si te sobra tiempo

Con Flask andando, cada cambio se ve al **guardar y recargar** el navegador. El `debug=True` hace
que se reinicie solo.

1. **Una marca más.** En `app.py`, agregale una `"P"` a Beto. Guardá, recargá `/alumnos`: ¿cambió el
   porcentaje?
2. **Un alumno más.** Agregá un tercer alumno al curso. ¿Aparece en `/alumnos` sin tocar
   `pagina()`?
3. **Un link por alumno.** Hacé que cada renglón de `/alumnos` sea un link a `/alumno/<su dni>`.
   ¿Qué función tenés que cambiar, y por qué alcanza con cambiar esa sola?
4. **Que se vea mejor.** Agregá un `<style>` al principio de lo que devuelve `pagina()`, con lo que
   aprendiste de CSS.

## Para llevar

```python
# Excepciones adentro de los objetos
raise ValueError("el DNI tiene que ser de 7 u 8 números")   # el dato no sirve: frenar

try:
    curso.agregar(Alumno(dni, apellido, nombre))
except ValueError as e:                                      # atajar, anotar y seguir
    errores.append(f"{dni}: {e}")

# Del objeto al HTML
f"<li>{alumno}</li>"                                         # usa el __str__

# Flask: una dirección, una función
@app.route("/alumnos")
def lista_de_alumnos():
    return pagina(curso)                                     # lo que devuelve es la página
```

- El HTML de una página web **es texto**, y Python sabe armar texto.
- **Flask** atiende los pedidos del navegador: por cada dirección llama a una función tuya.
- Los datos todavía viven **en memoria**: si cerrás `app.py`, las marcas nuevas se pierden. Eso lo
  resuelve **SQLite**, la clase que viene.
